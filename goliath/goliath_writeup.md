# Goliath

**Флаг:** `avito{h0NEy_BadgEr_p0PPed_7h3_wasM_saNDb0X}`

Goliath продолжает [David](../david/david_writeup.md): непроверенные смещения от
`Memory.data_ptr()` дают не только чтение, но и запись в память Python-процесса.
Чтобы получить файл `/flag`, достаточно изменить каталог объекта `StaticFiles`.

## Чтение и запись

Загруженный модуль управляет результатами `fen_buffer()` и `best_move()`. Python
записывает FEN по первому смещению и читает ответ по второму. Экспорты `i64` позволяют
адресовать память процесса за пределами WASM.

Модуль получает адрес из FEN вида `b"x b " + <8 байт адреса>`, читая его через
`i64.load @20`. Поле `b` сохраняет выбор `BADGER_PLAYER`. Один модуль обслуживает обе
операции, поэтому база памяти между чтением и записью не меняется.

`/flag` ещё не открыт процессом, так что поиск текста в памяти не помогает. Сам WASM
не импортирует системные вызовы. Используем уже существующий обработчик `StaticFiles`:
заменяем его корневой каталог `/app/web/dist` на строку той же длины `x b /../../..`.
При рабочем каталоге `/app` она разрешается в `/`, и `GET /flag` читает нужный файл.

## Поиск адреса StaticFiles

Для исследованного окружения — Linux, CPython 3.11, Wasmtime 45.0.0 — цепочка такая:

1. Несколько запросов по допустимому смещению 64 создают рабочий поток uvicorn.
2. Для `O = 0x206000000 + slot * 0x04000000` читаются значения `O+0x00` и `O+0xc38`.
   Первое указывает в ту же область памяти, второе содержит адрес возврата. Они дают
   базы `BADGER_PLAYER` и Wasmtime; GOT Wasmtime позволяет найти libc и проверить ELF.
3. По фиксированному адресу `_PyRuntime=0xa5c1c0` начинается обход объектов:

```text
_PyRuntime → interp → sys.modules → __main__ → APP → router → routes
           → Mount → StaticFiles → all_directories[0] → "/app/web/dist"
```

Перебираются `slot=(2,4,0,6,3,5,1,7,8)`. Неверный адрес завершает процесс; после
перезапуска модуль загружается заново. Эти адреса и порядок — свойства исследованной
сборки, а не гарантия для других версий.

Ответ API обрывается на NUL, поэтому указатель собирается из нескольких чтений.
На x86-64 нужны шесть младших байт. Обход учитывает два диапазона адресов ключей
словарей и две структуры записей: 24 байта при `dk_kind==0`, 16 байт иначе.

## Запуск

Архив сервиса включён в Git. Локальная проверка чтения памяти:

```bash
uv run python goliath/solve_goliath.py
```

Полная цепочка требует совместимого Linux-экземпляра:

```bash
uv run python goliath/solve_goliath.py --url https://goliath-srv-<id>.avitoctf.ru --full
```

Без `--full` сетевой режим проверяет только чтение памяти. При полном запуске скрипт
ищет адреса, меняет строку каталога и получает флаг через `GET /flag`.
