# Сопромёд — write-up (task3)

**Avito CTF 2026 · категория «Сеть»**

## 1. Условие задачи

Легенда: профессора Барсукова трясло в метро, он раз за разом мазал по клавишам и не мог войти
в СДО (систему дистанционного обучения). Весь его трафик утёк в открытый метро-Wi-Fi и попал к нам.
**Цель:** попасть в аккаунт профессора в СДО и забрать флаг.

**Дано:** `sopromed_capture.pcap` — дамп трафика.
**Боевой хост СДО:** `https://sopromed-vlrdcf4v.avitoctf.ru/`

**TL;DR идеи.** «Трясло, не попадал по клавишам» → в pcap открытый HTTP → 96 неудачных логинов →
пароль один, но с плавающими опечатками → **мода по столбцам** (мажоритарное голосование по позициям)
восстанавливает секрет → leet-фраза подтверждает его смыслом → вход → нужный API находится в JS-бандле
→ флаг в `GET /api/teacher/dashboard`.

## 2. Разведка

### Что за файл и что внутри

```bash
file sopromed_capture.pcap                       # pcap, Ethernet
capinfos sopromed_capture.pcap                   # 960 пакетов, длительность 570 с
tshark -r sopromed_capture.pcap -q -z io,phs     # иерархия протоколов
```

Важные наблюдения:
- encapsulation = **Ethernet** (не 802.11) — Wi-Fi уже расшифрован, прикладные данные в открытом виде;
- в иерархии протоколов `tcp → http → json`, HTTP-фреймы присутствуют;
- **960 пакетов за 570 с**. При ~96 обменах это ≈ одна попытка каждые 6 секунд — темп человека,
  упорно перевводящего пароль (а не автоматический перебор).

Вывод: логин/пароль лежат прямо текстом в HTTP-телах — надо их извлечь.

### Серия неудачных логинов

```bash
tshark -r sopromed_capture.pcap -Y http.request  -T fields -e http.request.method -e http.request.uri
tshark -r sopromed_capture.pcap -Y http.response -T fields -e http.response.code
```

Результат:
- **96× `POST /api/auth/login`**;
- **96× `401 Unauthorized`**, ни одного `200`.

Вывод: готового рабочего пароля в дампе **нет** — все попытки провалились. Пароль придётся
**вычислить** из этих 96 промахов.

### Тела запросов: структура опечаток

```bash
tshark -r sopromed_capture.pcap -Y http.request -T fields -e json.value.string
```

```
prof_barsukov,b4dver_zt34lz_y0nwy
prof_barsukov,g4dgef_st34ld_h0mey
prof_barsukov,b4dger_zt34ks_j0jsh
prof_barsukov,b4dger_dt34ls_n0ney
prof_barsukov,v4dger_st34pa_h0bsy
...
```

Три наблюдения, которые и задают метод:
1. **Логин везде один** (`prof_barsukov`) — меняется только пароль. Значит это повторный ввод
   **одного** секрета, а не перебор словаря.
2. **Все пароли одной длины (19) и одной формы** `XXXXXX_XX34XX_XXXXXX` — структура жёстко фиксирована,
   «съезжания» символов нет (это подтверждает, что человек метил в одни и те же клавиши).
3. **Ошибки «плавают» по позициям**: в каждой попытке испорчено немного символов и в разных местах.

Из п.3 следует ключевой вывод: раз в каждой отдельной позиции ошибок **меньшинство**, то
**правильный символ встречается в этой позиции чаще любого ошибочного**.

## 3. Уязвимость

Строго говоря, «уязвимость» тут — на стороне человека и модели ошибок ввода, а не сервера. Профессор
раз за разом набирает один и тот же пароль, промахиваясь по случайным соседним клавишам. Это
превращает 96 строк в **96 зашумлённых копий одного секрета** — классический канал с независимым
шумом по позициям. Такой шум снимается **избыточностью**: усредняем 96 «замеров» каждой позиции.
Дамп открытого Wi-Fi просто выдал нам все эти замеры в открытом виде.

## 4. Эксплуатация шаг за шагом

### Шаг 1. Голосование по столбцам (мода)

96 паролей — это таблица 96×19 (строка = попытка, столбец = позиция). Верный символ столбца — тот,
который профессор *хотел* нажать; ошибки случайны и размазаны по нескольким вариантам. Значит
**самый частый символ в каждом столбце и есть правильный**:

```python
from collections import Counter
lines = [l.strip().split(',')[1] for l in open('bodies.txt')]   # только пароли
print(''.join(Counter(col).most_common(1)[0][0] for col in zip(*lines)))
# -> b4dger_st34ls_h0ney
```

`zip(*lines)` транспонирует таблицу в столбцы; `Counter(...).most_common(1)` берёт моду каждого столбца.

Статистика подтверждает модель ошибок из легенды:

| Тип позиции | Частота лидера |
|---|---|
| Цифры и `_` (поз. 1, 6, 9, 10, 13, 15) | **96/96** — по ним не промахнулся ни разу |
| Буквы (поз. 0, 2, 4, …) | 40–61 из 96 — лидер есть всегда, с явным отрывом |

### Шаг 2. Проверка смыслом (независимое подтверждение)

Расшифровка leet: `b4dger`→**badger** (барсук ↔ «Барсуков»), `st34ls`→**steals**, `h0ney`→**honey**
(мёд ↔ «Сопромёд»). Получилась осмысленная фраза **«badger steals honey»**, идеально попадающая
в лор задачи. Статистика и семантика сошлись в одной точке — ответу можно доверять, не проверяя его
на сервере вслепую.

### Шаг 3. Вход в СДО

```bash
curl -sk -c cj.txt -X POST https://sopromed-vlrdcf4v.avitoctf.ru/api/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"prof_barsukov","password":"b4dger_st34ls_h0ney"}'
```

→ `HTTP 200` + кука `sopromed.sid`. В ответе `otp_enabled:true`, но сессия выдана и защищённые
эндпоинты открылись **без** второго фактора (по письму деканата 2FA нужна лишь «для доступа к эталонным
ответам», не для дашборда — это пригодится в task4).

### Шаг 4. Поиск флага

Это React-SPA, список API не виден на страницах — достаём его из JS-бандла:

Среди эндпоинтов — преподавательский `/api/teacher/dashboard`. С сохранённой кукой:

### Воспроизведение (полностью)

```bash
# 1. извлечь пароли из трафика
tshark -r sopromed_capture.pcap -Y http.request -T fields -e json.value.string \
  | sed 's/^prof_barsukov,//' > attempts.txt

# 2. восстановить пароль модой по столбцам -> b4dger_st34ls_h0ney
python3 -c "from collections import Counter;\
L=[l.split()[0] for l in open('attempts.txt')];\
print(''.join(Counter(c).most_common(1)[0][0] for c in zip(*L)))"

# 3. логин + флаг
curl -sk -c cj.txt -X POST https://sopromed-vlrdcf4v.avitoctf.ru/api/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"prof_barsukov","password":"b4dger_st34ls_h0ney"}'
curl -sk -b cj.txt https://sopromed-vlrdcf4v.avitoctf.ru/api/teacher/dashboard
```

## 6. Выводы / уроки

- **Главное — не инструмент, а вывод.** Ключ к задаче — понять, что 96 «мусорных» строк это **не**
  перебор словаря, а зашумлённые копии одного пароля.
- **Шум с независимыми ошибками снимается статистикой, а не гаданием.** Мода по столбцам —
  ремонт с исправлением ошибок через избыточность (майоритарное голосование).
- **Два независимых подтверждения надёжнее одного.** Статистика (мода) и семантика (осмысленная
  leet-фраза) сошлись — это резко снижает риск ошибки ещё до попытки логина.
- **Открытый Wi-Fi = открытый HTTP.** Пароль в теле POST виден любому, кто снимает трафик; здесь
  сам факт незашифрованного логина и подарил все «замеры» секрета.
