# David

**Флаг:** `avito{honey_badger_does_not_check_bounds_cf9ff3558ae0277f}`

Python-сервис принимает WASM-модуль и вызывает его экспорт `best_move`. Возвращённое
число используется как смещение от `wasmtime.Memory.data_ptr()` без проверки границ.
Так можно прочитать память соседнего модуля, где лежит флаг.

## Выход за границы WASM

В общем сервисе David/Goliath есть два игрока: серверный `BEE_PLAYER` и загружаемый
`BADGER_PLAYER`. Второе поле FEN выбирает игрока: `b` направляет запрос в наш модуль.

`fen_buffer()` задаёт место записи входной строки, а `best_move()` — место чтения
ответа. Python читает байты до NUL и возвращает строку в JSON. Тип экспортируемого
результата не проверяется: `i64` позволяет задать смещение больше 4 GiB.

```wat
(module
  (memory (export "memory") 1)
  (func (export "fen_buffer") (result i32) i32.const 0)
  (func (export "best_move") (result i64) i64.const 0x104000430))
```

В `mcu-max.wasm` флаг находится в `fen_buf` по смещению `0x430`. Для исследованной
Linux-сборки расстояние между областями памяти описывается так:

```text
offset = 0x104000000 + k * 0x04000000 + 0x430
```

Чаще срабатывали `k=0` и `k=2`. Неверный адрес вызывает `SIGSEGV`, после которого
контейнер перезапускается и размещение памяти меняется. Поэтому скрипт повторно
проверяет вероятные значения, а не исключает их после одного промаха.

## Запуск

Получите работающий экземпляр через launcher Goliath; CAPTCHA проходится вручную.
Затем:

```bash
uv run python david/solve_david.py --url https://<INSTANCE_HOST>/
```

Скрипт компилирует WAT, отправляет его через `POST /api/upload` и запрашивает
`GET /api/best-move?fen=x%20b`. При успехе поле `best_move` содержит флаг. После сбоя
скрипт ждёт запуска сервиса и загружает следующий модуль.

Смещения зависят от ОС, версии Wasmtime и размещения памяти. На другой сборке их
нужно определить заново.
