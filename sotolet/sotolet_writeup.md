# Сотолёт

**Флаг:** `avito{5ot0lE7_que3N_bEar1NG}`

nginx ограничивает доступ к административным хостам Сотолёта, но сами сервисы
доступны на публичных портах 8080 и 8443. Через pgAdmin можно прочитать реквизиты
диспетчера и войти в панель напрямую.

## Обход прокси

В исследованном экземпляре `84.201.131.80:8080` обслуживал pgAdmin в desktop-режиме:
`server_mode=False`, отдельного входа нет. CSRF-токен выдаётся в
`/browser/js/utils.js`.

В pgAdmin уже зарегистрирован PostgreSQL. Подключение через
`/browser/server/connect/1/1` под ролью `bee` принимает пустой пароль. Затем
инициализируется Query Tool с `dbname=sotobaza` и выполняется:

```sql
SELECT * FROM dispatchers;
```

В ответе находятся реквизиты старшего диспетчера:
`starshina_sot / SMENA-STARSHINA-7741`, роль `chief`.

## Получение маршрута

Панель диспетчера доступна по HTTP на порту 8443:

```bash
curl -s -c kcj -X POST http://84.201.131.80:8443/login \
  --data-urlencode 'login=starshina_sot' --data-urlencode 'password=SMENA-STARSHINA-7741'
curl -s -b kcj http://84.201.131.80:8443/api/admin-data
```

Флаг находится в маршруте `queen-route`. Прямое чтение сырых строк базы не заменяет
этот шаг: маршрут раскрывается приложением после проверки роли.

## Запуск

[solve_sotolet.py](solve_sotolet.py) получает CSRF-токен, выполняет SQL-запрос,
входит в панель и читает флаг:

```bash
uv run python sotolet/solve_sotolet.py --ip <текущий-IP>
```

Адрес выше зафиксирован во время соревнования. Для нового экземпляра нужны его IP
и доступные порты; параметры `--pgadmin-port` и `--dispatcher-port` позволяют их задать.

ACL на прокси не защищает открытые порты самого приложения. Их нужно закрыть
от внешней сети; pgAdmin должен требовать вход и отдельные реквизиты базы.
