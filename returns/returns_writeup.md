# Возвратов.net

**Флаг:** `avito{MaKE_a_refUND__4n_3V1l_hON3Y_baDGER_Ha5_COM3_TO_Me}`

Cookie `session` содержит JWT с адресом Redis, логином, паролем и ID сессии.
Этих данных хватает, чтобы изменить сохранённое решение о возврате. Эскалация доверяет
такой записи и выдаёт ваучер с флагом.

## Подмена решения

JWT подписан, но его содержимое не зашифровано. Redis доступен извне, а выданная
учётная запись может читать и менять общий набор ключей.

Сначала обычный диалог с агентом «Лев» создаёт `SystemMessage` с текстом
`RETURN_DECISION: denied`. Процесс `escalation-review` берёт последнее такое сообщение
из Redis и не проверяет, кто его записал.

Скрипт находит список `<uid>_space:support:<sid>` через `SCAN`, читает его `LRANGE`
и заменяет нужный элемент командой `LSET`: `denied` становится `approved`, остальные
поля сообщения сохраняются. После запроса эскалации сессия получает `status: review`,
а затем `result.voucher` с флагом. Уговаривать модель принять решение не требуется.

## Запуск

Для новой заявки нужен токен reCAPTCHA:

```bash
uv run python returns/solve_returns_redis.py --captcha '<reCAPTCHA-token>'
```

Либо используйте cookie существующей сессии, сохранённую в файл:

```bash
uv run python returns/solve_returns_redis.py --session @session.txt
```

[solve_returns_redis.py](solve_returns_redis.py) выполняет всю цепочку, включая RESP
поверх обычного TCP-сокета. Нужен доступ к Redis из JWT. Файл с cookie не включается в Git.

Исправление — не передавать клиенту реквизиты Redis, ограничить права на записи
и хранить решение о возврате отдельно от изменяемой истории диалога.
