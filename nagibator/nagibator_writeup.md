# Нагибатор

**Флаг:** `avito{nO_diScoUn7_15_NeEded_whEN_Y0U_haVE_rc3}`

Нагибатор сериализует пользовательские поля через `pickle` protocol 2 и передаёт их
backend в Base64 через form-urlencoded. Неэкранированный `+` превращается в пробел,
который Base64-декодер игнорирует. Этот сдвиг превращает данные большого числа в команды pickle.

## Повреждение LONG1

Поле `pressure` — большое целое, сериализуемое инструкцией `LONG1`. При длине
`0xF8` (248 байт) её представление в Base64 содержит нужный `+`. После удаления одного
шестибитного символа поток сдвигается, а длина `LONG1` становится нулевой.

Оставшиеся байты числа теперь читаются как инструкции pickle. Скрипт вычисляет
исходные байты так, чтобы после сдвига получился вызов `builtins.eval`. Последний байт
`data[247]=0x01` сохраняет нужную длину положительного целого при сериализации.

Запрос содержит поля:

```text
discount=30&time_amt=00%3A30&trumps=other&extra=<кириллица>&pressure=<большое целое>
```

Поле `extra` перебирается для подходящего расположения байтов. Ответ класса `REFLECT`
показывает, что исключение от вычисленного выражения вернулось клиенту.

## Получение флага

Сначала выражение проверяет пути `/*flag*`, `/app/*flag*` и переменные окружения с
`FLAG` в имени. Затем выполняется:

```python
int(open('/flag.txt').read())
```

Преобразование заведомо не удаётся. `ValueError` содержит прочитанную строку с флагом;
`File "<string>", line 1` в трассировке подтверждает выполнение через `eval`.

```bash
uv run python nagibator/solve_nagibator.py
```

[solve_nagibator.py](solve_nagibator.py) строит исходный `LONG1`, перебирает `extra`
и получает флаг. Нужен работающий экземпляр; адрес задан в скрипте.

Корневая проблема — `pickle.loads` на данных клиента. Корректное URL-кодирование
закроет этот способ повреждения потока, но не сделает недоверенный pickle безопасным.
