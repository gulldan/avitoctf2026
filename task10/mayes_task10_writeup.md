**Avito CTF 2026 · crypto (netcat oracle)**
**Цель:** разгадать шифр «Майес», пройти `login`, отключить рассылку.
**Сервис:** `nc maya-iiklm8rm.avitoctf.ru 30013`, сэмпл-секрет `v3FpEne80zLFyP1rOfj5rQ`.

## Флаг

Получен из админ-меню (пункт отключения рассылки) после сдачи восстановленного plaintext.
`avito{…}` ← _впиши точное значение_.

## Ключевая зацепка (которую сначала упустили)

MAYES — это простой **3-слойный SPN**, и **режим `debug` показывает промежуточный результат после КАЖДОГО слоя**:
```
Msg to encrypt: ...
After layer 01: ...
After layer 02: ...
After layer 03: ...
ciphertext:     ...
```
Это превращает задачу из «чёрного ящика» (где мы честно мерили структуру и думали про брутфорс/ASASA) в **белый ящик**: каждый слой восстанавливается напрямую подачей контролируемых входов. Мораль на будущее: прежде чем строить сложную атаку — до конца выжми, что даёт сам сервис (тут debug-утечка по слоям решала всё).

Схема: `P ──L1──> X1 ──L2──> X2 ──L3──> C`.

## Слой 1 — XOR с ключом

Отправили нулевой блок `P = 00…00`; сервер показал `After layer 01: 90d54ee6…`. То есть:
```
L1(P) = P XOR K   →   для нулей   0…0 XOR K = K
```
Значит на нулевом входе `After layer 01` — это и есть **весь ключ**.

## Слой 2 — побайтовая подстановка (S-box)

Подавали входы так, чтобы после XOR получить контролируемые байты на выходе слоя 1, и читали слой 2:
```
After L1: 00 00 …  → After L2: 51 51 …
After L1: 01 01 …  → After L2: 4d 4d …
After L1: 02 02 …  → After L2: d3 d3 …
```
Видно, что слой 2 обрабатывает **каждый байт независимо одной и той же таблицей** (S-box): `00→51`, `01→4d`, `02→d3`, … Собрали полную таблицу локально и построили **обратную**: `51→00`, `4d→01`, `d3→02`. Дешифровка слоя 2 = поиск по обратной таблице.

## Слой 3 — линейное перемешивание по 4 байта (матрица)

Слой 3 работает группами по 4 байта. Подавали единичные векторы:
```
01 00 00 00 ,  00 01 00 00 ,  00 00 01 00 ,  00 00 00 01
```
и по выходам восстановили матрицу перемешивания (умножение над GF(2⁸)):
```
e1 c6 fa a6
b8 a9 59 66
95 1f f0 35
22 24 d2 7d
```
Обратная матрица (расшифровка слоя 3):
```
5d b2 08 f6
0d 64 e5 65
c3 09 e7 c9
0c b2 96 6b
```

## Дешифровка (обратные слои в обратном порядке)

**Ключ из «нулевой» утечки.** Сервер сообщил `E(00…00) = 855350f1b32af79d559524cff5d50f52`. Идём строго назад:
```
855350f1b32af79d559524cff5d50f52
  ↓ обратная матрица слоя 3
1dd2a38dd163f9f18564ff335f6a07a6
  ↓ обратная таблица слоя 2
0c3a9ebde2f3e5d30710eb7383685132   = X1 = 0…0 XOR K = K
```
→ **K = `0c3a9ebde2f3e5d30710eb7383685132`** (plaintext был нулевой, поэтому X1 = K напрямую).

**Настоящий challenge.** Для ciphertext `0d16c74754bb276063c3e82773bde609`:
```
ciphertext
  ↓ обратный слой 3
  ↓ обратный слой 2
  ↓ XOR с ключом K
= 14783b2b8bdf2d7f45e5e36bd2996c4a   ← это и есть plaintext
```
Отправляем `14783b2b8bdf2d7f45e5e36bd2996c4a` серверу → `Access granted!` → в админ-меню выбираем «отключить рассылку» → флаг.

## Полный алгоритм решения

1. Авторизоваться сэмпл-секретом `v3FpEne80zLFyP1rOfj5rQ`.
2. В `debug` восстановить правила слоёв: L1 = XOR K (по нулям), L2 = S-box (по байтам 00/01/02/…), L3 = матрица 4×4 (по единичным векторам); построить обратные L2⁻¹, L3⁻¹.
3. В `login` взять challenge-ciphertext C (ключ K фиксирован на сессию).
4. Обратить: `P = K XOR L2⁻¹(L3⁻¹(C))`.
5. Отправить P → доступ инженера → отключить рассылку → флаг.

Скрипт-солвер — `task10/solve.py` (с восстановленными S-box и матрицей).

## Мораль

Шифр — по сути **один раунд AES-подобного SPN** (AddRoundKey → SubBytes → MixColumns), без ShiftRows (поэтому 4-байтовые группы независимы — это мы и намерили как «AES без ShiftRows»). Но ломать его брутом/структурно не понадобилось: **сервис сам в debug печатал выход каждого слоя**, что делает восстановление S-box и матрицы тривиальным (подал контролируемые входы — прочитал таблицу/матрицу). Урок №1 — всегда до конца исследуй, что отдаёт сам сервис; утечка промежуточных состояний = мгновенный белый ящик. Урок №2 — SPN без диффузии между словами (без ShiftRows) распадается на независимые маленькие блоки.
