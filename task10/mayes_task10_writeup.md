## 1. Условие (кратко)

Пчёлка Майя каждый день шлёт паническую рассылку про «конец света 21.12.2026».
Найден её сервер, но **токен входа зашифрован неизвестным шифром «Майес»**.
Нужно разгадать шифр, войти и **отключить рассылку** → флаг.

**Сервис:** `nc maya-iiklm8rm.avitoctf.ru 30013`
**Образец секрета:** `v3FpEne80zLFyP1rOfj5rQ` (22 символа, base62-подобный — валидный access-токен).

## 2. Разведка: протокол сервиса (полностью размечен)

После `Enter secret:` + образца секрета — админ-меню из трёх пунктов:
**1) login  2) debug  3) exit** (карта в шапке `solve.py`, проверялась `chain.py`, `dbgcmd.py`, `menu.py`).

### Оракул A — `login` (главный, ограниченный)

```
New key has been generated: 16 bytes
Login: 5 attempts available. Decrypt the given ciphertext ...
ciphertext #1: <32 hex>        <- C = MAYES_K(P), P — случайные 16 байт
plaintext> _
```

- неверная длина/не-hex → `Error: expected exactly 16 bytes` + НОВЫЙ ciphertext;
- верные 32 hex, но **неправильный** guess `G` →
  `Authentication failed. Your plaintext encrypts to <MAYES_K(G)>.` + НОВЫЙ ciphertext;
- **правильный** guess (`MAYES_K(G) == C`) → `Access granted!` (админка).

Вот ключевое наблюдение: раз при неверной попытке сервер **сам печатает `MAYES_K(G)`**, то
**сам prompt логина — это chosen-plaintext ENCRYPTION-оракул** (шифруем выбранные нами блоки),
лимит — 5 обращений, а ключ `K` **фиксирован на всю сессию логина**. Это и есть точка входа для атаки.

### Оракул B — `debug` (безлимитный, но «не тот» ключ)

```
Debug key has been loaded: d6****....97        <- показывает только key[0] и key[15]
Debug cipher: encrypts a 16-byte hexadecimal block ...
plaintext> _        -> БЕЗЛИМИТНЫЙ MAYES_K-оракул, отдаёт одну строку "ciphertext:"
```

Что здесь важно и что подтверждено измерениями (`solve.py`, `analyze.py`):

- debug отдаёт **только финальный** `ciphertext:` — промежуточных состояний по слоям он НЕ печатает;
- debug-ключ == ключу **последней** login-сессии, и **каждый новый login перегенерирует ключ**
  (свежий `os.urandom`-подобный). Значит debug годится только чтобы **изучать алгоритм**,
  но это всегда ключ логина, который ты уже покинул, — им нельзя ответить на текущий challenge.

Отсюда стратегия: **структуру шифра учим в безлимитном debug**, а **боевой ключ ломаем в 5 попытках login**.

## 3. Структура шифра «Майес» (измерено оракулом)

Всё ниже — прямые измерения (`analyze.py` флипает входные байты и смотрит, какие выходные меняются;
`square.py`/`square2.py` — интегральные/Square-тесты; C-файлы — 2³² перебор известных шифров).

- **Блок 16 байт распадается на ЧЕТЫРЕ НЕЗАВИСИМЫХ 32-битных слова.** Входной байт `i`
  влияет только на выходное слово `i//4` (проверено для всех байтов). То есть Майес =
  **4 параллельных 32-битных шифра**, каждый со своим 4-байтным срезом ключа
  (`key[0:4]` → слово0, … `key[12:16]` → слово3).
- Каждое 32-битное слово: **биекция, полная лавина, детерминированность**. НЕ XOR-аффинно,
  не аддитивно, без рефлексии/инволюции.
- **Это «AES без ShiftRows».** Именно ShiftRows связывает столбцы AES; без него AES вырождается
  в 4 независимых 32-битных «столбцовых» шифра — ровно то, что мы намеряли.
- **Побайтовый SPN:** интеграл (zero-sum) держится на ВЫХОДЕ для каждого байт-выровненного
  активного входного байта, но общая алгебраическая степень высокая (случайные 15-кубы
  ненулевые → deg ≥ 15). Отпечаток `log2(#различных значений)` вход-байт → выход-байт:
  ```
  [[8,5,8,7],
   [7,8,8,6],
   [7,8,4,7],
   [7,7,8,8]]
  ```
  Матрица **неоднородна** ⇒ линейный слой бит-ориентированный, **не MDS**, это **НЕ** GF(2⁸)-MixColumns из AES.

### Что перепробовали и отбросили (и почему это ценно)

Каждый закрытый вариант сужает пространство:

- **Square/интеграл с матрицей AES** (`square.py`, `square2.py`): пилинг финального
  «MixColumns+AddRoundKey» с AES-матрицей/InvMC — во всех 24 байтовых ориентациях и 2 lambda-наборах
  **согласованного ключа последнего раунда НЕ нашлось** → линейный слой не AES-евский.
- **Прямой 2³²-перебор известных шифров** (C: `speck32/64`, `simon`, `rc5`, `miniaes`, `sprot`):
  все дали `NO HIT` (см. `speck_result.txt`, `miniaes_out.txt`, `sprot_out.txt`, `brute3_out.txt`).
  Проверяли разные раунды/расписания/эндианность.

**Вывод:** Майес — **кастомный per-column шифр** (раскладка «AES без ShiftRows», собственные S-box
и/или бит-ориентированный линейный слой). Его точная round-функция — в **исходнике задачи**.

## 4. Уязвимость (почему это вообще ломается)

Не криптографический «баг», а **структурная слабость раскладки**: без ShiftRows 128-битный шифр
распадается на **4 полностью независимых блока по 32 бита**, каждый под **32-битным** подключом.
32 бита ⇒ ключ каждого слова **перебираем офлайн** из 1–2 chosen-plaintext пар. А пары нам бесплатно
даёт сам login-оракул (печатает `MAYES_K(G)` на неверную попытку). Поэтому лимита в 5 обращений
хватает: 1–2 уходит на сбор пар, остаток — на отправку восстановленного plaintext.

(Данные для офлайн-перебора уже собраны в `pairs.json` — по каждому слову таблицы `(pt32 → ct32)`,
напр. слово0: `00000000→99c752c6`, `00000001→5d0ba044`, … — и в `w0data.json` для слова 0.)

## 5. План эксплуатации (нужна round-функция из исходника)

Каркас полностью реализован в `solve.py`; единственная заглушка — `mayes_word_encrypt` / `_decrypt`.

1. Авторизоваться образцом секрета `v3FpEne80zLFyP1rOfj5rQ`.
2. `login` → прочитать challenge `C`, разбить на 4 слова `c0..c3`.
3. Отправить один выбранный guess `G = 00…00` → получить `E_K(0)` (по одной CP-паре на слово);
   при неоднозначности — второй guess `G = 01…01` (тратим 2 попытки, остаётся 3).
   ```python
   for g in (bytes(16), bytes([1]*16)):
       granted, rev, _ = svc.login_guess(g)   # rev = MAYES_K(g), печатается сервером
   ```
4. Офлайн: для каждого слова `i` перебрать все 2³² подключа `k` с
   `mayes_word_encrypt(k, 0) == E_K(0)_i` (сверить второй парой) → восстановить `k_i`
   (функция `brute_word_key` в `solve.py`).
5. Офлайн: `P_i = mayes_word_decrypt(k_i, c_i)` → склеить `P` = plaintext всего `C`.
6. Отправить `P` в той же 5-попыточной сессии → `Access granted!`.
7. В админ-меню выбрать пункт «отключить рассылку / disable» → **флаг**.

> Незакрытый пункт: точная round-функция 32-битного блока (кастомные S-box / линейный слой).
> Пока `mayes_word_encrypt` не заполнен из исходника задачи, шаги 4–7 не выполняются,
> поэтому `Access granted!` и флаг в артефактах не зафиксированы.

## 7. Выводы / уроки

- **Сначала измерь структуру, потом строй атаку.** Флипы входных байтов (`analyze.py`) сразу показали,
  что 128-битный блок — это 4 независимых 32-битных слова. Это меняет сложность с «неподъёмной»
  на «2³² на слово, перебирается офлайн».
- **Раскладка решает.** «AES без ShiftRows» = отсутствие диффузии между словами ⇒ шифр рассыпается на
  маленькие независимые блоки. ShiftRows не декоративен: он склеивает столбцы.
- **Оракул на «неудаче» — это оракул.** Login печатал `MAYES_K(G)` даже при неверной попытке, то есть
  форма аутентификации превратилась в **chosen-plaintext encryption oracle** — источник пар для перебора.
- **Отделяй «изучение» от «боя».** Безлимитный debug — для анализа алгоритма; ограниченный login с
  фиксированным на сессию ключом — для собственно взлома challenge.
- **Честность про недостающее.** Известные шифры (Speck/Simon/RC5/mini-AES) отвергнуты перебором
  (`NO HIT`); значит round-функция кастомная и берётся из исходника — без неё финальный логин не собрать.
