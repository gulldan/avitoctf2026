## Архитектура (восстановлена по утечкам трейсбеков)

- **Фронтенд** `/app/frontend.py` (Flask, `debug=OFF`). Для *неожиданных* исключений в `validate()` отдаёт клиенту `traceback.format_exc()` — это дало «карту кода» без исходника (строки 34 `int(discount)`, 39 `int(pressure)`, 44 `strptime(time_amt,'%H:%M')`, 63 `safe_validate`). Именно эта утечка — то, что видно при «смотреть пути»/питон-3.7-ошибке.
- **Бэкенд** `/app/backend.py` — **отдельный сервис**, не выставлен на публичный домен. Фронт делегирует ему «кастомную стратегию» и **пробрасывает его трейсбек** клиенту как JSON `{"detail","error","traceback"}`.
- **Sink:** `File "/app/backend.py", line 204, in strategy` → `obj = pickle.loads(raw)`. `pickle.loads` недоверенных байт = RCE.

## Как устроен выбор стратегии (по 2500-запросному скану)

`bucket = H(входы)` — псевдослучайный хеш-бакет. Пространство `extra` = **8 бакетов**: 7 локальных персонажей (Оптовик, Берсерк, Мать троих ангелочков, Сосед, Пенсионер, Снайпер, Заберу сейчас) + 1 «бэкенд-бакет», который **всегда** падает на pickle. Комбинации козырей и экстремальный `pressure` — просто другие бакеты того же механизма. Магического «валидного» бакета с флагом нет.

## Почему в pickle не войти (перепроверено в этой сессии)

| Гипотеза канала в `raw` | Тест | Итог |
|---|---|---|
| `extra` (any encoding) | свип по словам/кодировкам | `raw` не зависит — тот же байт ошибки |
| `pressure` / `discount` / `time_amt` | развёртки значений | не меняют `raw` (только выбор бакета / порог делегирования) |
| профиль (surname/firstname/email) | 2 очень разных профиля, все бакеты | ошибка байт-в-байт идентична |
| произвольное поле/тело/заголовок | **свип 101 тест** с валидным pickle-маркером `PWNED` | **0 девиаций** |
| произвольный `trumps` (не из 6) | инъекция | → дефолт-персонаж, `raw` не трогает |

Дополнительно исключено: **SSTI/XSS** (`{{7*7}}`→буквально `{{7*7}}`, `<b>"'&`→полностью HTML-экранировано; `extra` отражается в блоке «Козыри» через безопасный автоэкранированный Jinja); **инъекция в email** (валидатор хранит только чистый префикс — хвост `<script>` отбрасывается); утечка трейсбеков из `/save`/`/load` (устойчивы); **стего в картинках** (чистые JPEG, ничего после маркера `FFD9`); скачиваемый исходник/бэкапы (нет); `SECRET_KEY` (не подобран); `/docs`,`/openapi.json`, vhost-фаззинг Host, альт-порты (бэкенд внутренний, недостижим из песочницы).

Про **Python 3.7**: под наш вход (int, strptime, enum, ≤40-байтный `extra`, валидируемый профиль) ни одна библиотечная CVE 3.7 не доводит до флага. Единственный реальный deserialization-баг — это pickle, а он требует контроля байтов.

## Вывод: где вход на самом деле

`strategy()` ≈ `raw = BLOBS[H(входы)]; pickle.loads(raw)`, где `BLOBS` — серверный per-процесс стор случайных блобов, на который **ни один публичный вход не влияет**. Значит управляемые байты попадают в этот `pickle.loads` только:
1. **Прямым обращением к бэкенду** (внутренний сервис) — вероятнее всего, из **сети участника Avito** (ровно как в соседней задаче brainwash: «порт мёртв» из песочницы Claude = артефакт egress, работает из сети Avito). Из песочницы порты 8000/8001/8080/5000 давали быстрый connect + пустой ответ (nginx `444`) — из реальной сети картина может отличаться.
2. Либо через вход, задокументированный в **исходнике** бэкенда (специфичное поле/заголовок/путь), который black-box не угадать.
