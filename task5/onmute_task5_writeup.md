# OnMute — write-up (task5)

**Avito CTF 2026 · категория «Web / анализ исходников»**
**Цель:** обойти цензуру музыкальной площадки и достать полные (оригинальные) тексты треков. Флаг спрятан в одном из треков.
**Дано:** `onmute_a003aa0.zip` (исходники), боевой хост `https://onmute-xtegmx4v.avitoctf.ru/`.

## Флаг

Флаг лежит в **оригинальном** (нецензурированном) тексте трека №4 «Свожу куски к ключам»:

```
...Забираю своё. Вот он - ключ. Вот он - флаг:
🚩 avito{...}
```

В исходниках значение вырезано как `avito{/*REDACTED*/}` — реальный флаг отдаёт только боевой сервер по команде `/original 4` (см. эксплойт ниже). Плюс к нему автор припрятал **невидимую «отсылку для своих»** (см. раздел про стего).

## Архитектура и где прячется оригинал

- Данные треков лежат в Redis (`seed.js`), у каждого трека два поля: `censored` и `original`.
- Публичное API отдаёт **только цензуру**: `models/tracks.js` → `listTracks`/`getTrack` возвращают `text: censored`. Функция `getOriginalText(id)` (возвращает `original`) наружу напрямую не торчит.
- Единственный путь к оригиналу — **чат-бот** под треком. `POST /api/tracks/:id/comment` c `{text}` парсит команды (`bot/commands.js`), среди которых:
  - `/original <track_id>` — «показать оригинальный текст без цензуры» → вызывает `getOriginalText` и возвращает оригинал.
- Но перед выполнением команды комментарий проходит фильтр модерации, и **`/original` внесён в блоклист** (`moderation/blocklist.js`, первая строка `'/original'`). То есть в лоб команда `/original 4` блокируется как «запрещённое слово».

## Уязвимость: stateful-регексп с флагом `g` (десинхрон `lastIndex`)

Вся модерация в `moderation/filter.js` строится на **одном объекте `RegExp`, закэшированном на сессию** в `Map policies`:

```js
re: new RegExp(`(?:${BLOCKED_WORDS.join('|')})(?=[\\s.,!?;:)}\\]"'»]|$)`, 'gi')
```

Этот **один и тот же** объект используют две функции:

- `checkContent(text)` — сканирует комментарий циклом `while ((m = re.exec(text)) !== null)`. Когда `exec` не находит совпадений, он возвращает `null` и **сбрасывает `re.lastIndex` в 0**. То есть сам по себе `checkContent` консистентен.
- `matchesPolicy(fragment)` — вызывается из обработчика `/censor` и делает `re.test(fragment)`. У регекспа с флагом `g` метод `test` при **совпадении** сдвигает `re.lastIndex` на конец найденного слова и **НЕ сбрасывает** его.

Итог: после `/censor`, чей фрагмент совпал с запрещённым словом, у сессионного регекспа остаётся `lastIndex > 0`. Следующий вызов `checkContent('/original 4')` начинает `re.exec` **не с нуля, а с этого `lastIndex`**, поэтому **проскакивает `/original` в начале строки**, не находит других запрещённых слов в хвосте `"nal 4"`, возвращает `null` → `blocked = false`. Фильтр ослеп — управление уходит в `parseCommand('/original 4')`, команда выполняется и бот отдаёт **оригинальный текст** трека с флагом.

Ключевые детали, делающие баг реальным:
- Регексп кэшируется на сессию (`policies.get(sessionId)`), а сессия стабильна по httpOnly-куке `onmute_sid` (`middleware/session.js`) — состояние `lastIndex` переживает запросы.
- `/censor` сам по себе фильтр проходит (в тексте `"/censor 617 623"` запрещённых слов нет), а `matchesPolicy` проверяет уже **вырезанный фрагмент** трека — там мы и подсовываем запрещённое слово.
- В лоб `/original 4` не пройдёт: `/original` стоит первым в блоклисте, за ним пробел (разделитель из lookahead) → совпадение. Нужен именно предварительный «прайминг» `lastIndex`.

## Эксплойт (в рамках одной сессии, два запроса подряд)

1. **Прайминг `lastIndex`.** Отправить `/censor`, чей фрагмент — запрещённое слово. В цензуре трека №1 слово `массаж` стоит на позициях `617..623` (следующий символ — запятая):
   ```
   POST /api/tracks/1/comment
   {"text": "/censor 617 623"}
   ```
   `fragment = "массаж"` → `matchesPolicy` → `re.test("массаж")` = true → `re.lastIndex = 6` (запоминается на сессии).

2. **Обход фильтра и чтение оригинала.** Тем же кукисом сразу следом:
   ```
   POST /api/tracks/4/comment
   {"text": "/original 4"}
   ```
   `checkContent` стартует с `lastIndex = 6`, проскакивает `/original`, `blocked = false` → выполняется команда `/original 4` → бот возвращает оригинальный текст трека №4 с `🚩 avito{...}`.

> Примечание: аргумент трека берётся из самой команды (`cmd.trackId`), а не из URL, поэтому `/original 4` можно слать на эндпоинт любого трека. Главное — тот же кукис и порядок: сначала `/censor` (прайминг), сразу затем `/original 4`, без других запросов между ними, чтобы `lastIndex` не сбросился.

### Пример запросов (curl)

```bash
# 1) получить сессию + прайминг lastIndex через /censor на запрещённом слове
curl -s -c jar https://onmute-xtegmx4v.avitoctf.ru/api/tracks/1/comment \
  -H 'Content-Type: application/json' -d '{"text":"/censor 617 623"}'

# 2) тем же кукисом — обойти фильтр и прочитать оригинал трека 4
curl -s -b jar https://onmute-xtegmx4v.avitoctf.ru/api/tracks/4/comment \
  -H 'Content-Type: application/json' -d '{"text":"/original 4"}'
# -> в message придёт полный текст с 🚩 avito{...}
```

## Скрытая «отсылка для своих» (Unicode Tag стего)

В `original` трека №4 сразу после 🚩 идёт цепочка **невидимых Unicode-символов** из блока Tags (кодпоинты `U+E01xx`). Та же цепочка вшита в ответ бота на заблокированный комментарий (`routes/comments.js`, строка с `⛔…`). Это и есть «отсылка для своих», которую «тоже вырезали» — она невидима в обычном тексте.

Декодирование: каждый символ — это ASCII со смещением `0xE00F0` (`ascii = codepoint − 0xE00F0`):

```python
msg = ''.join(chr(ord(c) - 0xE00F0) for c in text if 0xE0100 <= ord(c) <= 0xE01FF)
```

Результат:

```
good job, take your hidden flag: https://mutedgift-9oevcdih.avitoctf.ru/
```

То есть скрытое послание указывает на бонус-URL `https://mutedgift-9oevcdih.avitoctf.ru/`.

## Итог

- **Полные тексты** достаются командой бота `/original <id>`, которая в лоб заблокирована блоклистом.
- **Обход цензуры** — десинхрон `lastIndex` у общего `RegExp('g')`: `/censor` на запрещённом слове двигает `lastIndex` через `re.test`, а следующий `checkContent` из-за этого проскакивает `/original`.
- **Главный флаг** — в оригинале трека №4 (`avito{...}`, реальное значение — с боевого сервера).
- **Отсылка для своих** — невидимая Unicode-Tag строка `https://mutedgift-9oevcdih.avitoctf.ru/` (смещение `0xE00F0`), спрятанная в тексте и в ответах бота.

## Мораль (почему это баг)

Регекспы с флагом `g`/`y` **хранят состояние** (`lastIndex`). Переиспользовать один такой объект для разных строк и разных функций (`exec`-скан и `test`-проверка) нельзя: одно совпадение сдвигает указатель и «ослепляет» следующую проверку. Правильно — компилировать регексп заново на каждый вызов либо сбрасывать `re.lastIndex = 0` перед проверкой (и не смешивать `test`/`exec` на общем объекте).
