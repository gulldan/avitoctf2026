# Botnet

**Флаг:** `avito{the_bo7ne7_15_CompL3tely_ComPRomISed}`

В начальном контейнере доступны только Bash и `base64`. Этого хватает для чтения
`/proc/net/*`, TCP-запросов через `/dev/tcp` и загрузки слоя Docker-образа с флагом.

## Решение

1. По `/proc/net/route` и `/proc/net/fib_trie` определить адрес и подсеть контейнера.
2. Найти соседний сервис на порту `5000`. В исследованном экземпляре это Docker Registry
   по адресу `network+2` в сети `/26`.
3. Прочитать `/root/.docker/config.json`. Запись `registry:5000` содержит Basic Auth:
   `YWRtaW46c3Ryb25ncGFzcw==`, то есть `admin:strongpass`.
4. Запросить `/v2/_catalog`, затем теги, манифест и конфигурацию образа `fastapi`.
   Последняя запись истории сборки указывает на `COPY ... in /app/flag.txt`.
5. Скачать соответствующий слой и извлечь `app/flag.txt` локально.

Bash-переменные не сохраняют NUL-байты. Поэтому двоичный ответ Registry передаётся
через `base64`, а HTTP-заголовки, gzip и tar разбираются уже на локальной машине.
Весь поиск выполняется в одной SSH-сессии: новое подключение может создать другой
контейнер с другими адресами.

## Запуск

Нужны действующие SSH-доступ и пароль. Скрипт использует системный `ssh` и Python:

```bash
uv run python botnet/solve_botnet.py --help
BOTNET_PASS='<пароль экземпляра>' uv run python botnet/solve_botnet.py
```

Адрес и остальные параметры доступны в `--help`. Пароль не задан в коде.
[solve_botnet.py](solve_botnet.py) автоматизирует поиск Registry, загрузку слоя и
извлечение флага. Результат сохранён в [FLAG.txt](FLAG.txt).

Причина доступа — доступные контейнеру реквизиты Registry и слой образа с секретом.
Удаление файла в следующем слое не удаляет его из истории образа.
