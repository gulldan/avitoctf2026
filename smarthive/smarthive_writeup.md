# SmartHive

**Флаг:** `avito{SmAr7_G4te_meaNS_eA5y_HonEy}`

Пользователь `bee4` читает отладочный журнал, в который попадают параметры входа.
Маскирование через `replaceFirst` скрывает лишь первое `password=` в строке. Гонка
записи позволяет поместить перед настоящим паролем свой ложный параметр.

## Гонка журнала

`RequestLoggingFilter` записывает большие тела запросов частями по 8 KiB. При
одновременном входе `BeeEng` и записи большого запроса фрагменты могут оказаться
в одной физической строке журнала.

Тело атакующего начинается с `password=ZZDECOYZZ&username=`. Если оно вклинится
перед записью `BeeEng`, `replaceFirst` скроет `ZZDECOYZZ`, а настоящий пароль останется.
Его можно найти выражением:

```regex
password=([^&\s]{1,120})&remember=true&username=BeeEng
```

Вход `BeeEng` запускается отключением устройства через
`POST /api/devices/hive-speakers/power?enabled=false`. Полученная учётная запись
имеет роль `ENGINEER`; запрос `/api/devices/landing-gate/open` возвращает флаг
в поле `serviceToken`.

## Запуск

Начальные реквизиты задания — `bee4 / MusicIsLife123`:

```bash
uv run python smarthive/exploit.py \
  https://smarthive-srv-vzzgazuy.avitoctf.ru bee4 MusicIsLife123
```

[exploit.py](exploit.py) входит в сервис, очищает журнал, запускает вход инженера
и отправляет параллельные запросы. В исследованной попытке использовались около
100 потоков и тела размером 700–800 KiB. Параметры `SIZE`, `NTH`, `DELAY`, `READ_LINES`
и `ATTEMPTS` настраиваются под экземпляр; результат зависит от планирования потоков.

[task.md](task.md) содержит исходные условия. Для исправления нужно исключить пароли
из журналирования и записывать события целиком. Замена `replaceFirst` на полное
маскирование устраняет лишь одну часть ошибки.
