# HoneyVault

**Флаг:** `avito{Un1X_SOCK3T_Race_4nD_5TICkY_SymLinK_3XP3rT}`

Решение начинается в контейнере `analyst`: через SMB находится пароль соседнего
storage-сервера. На нём гонка проверки Unix-сокета позволяет заказать архив от root
и включить в него `/root/flag.txt` через символическую ссылку.

## Доступ к storage

Встроенный DNS Docker разрешает имя `hv-storage-01`, хотя хост не отвечает на ICMP:

```bash
getent hosts hv-storage-01
smbclient -N //hv-storage-01/data -c 'get admin/linux/remote-backup.sh'
```

В скрипте лежит MD5-crypt хэш пользователя `operator`:
`$1$lp9yekC1$OhCfwi88S6riHT9rovIqy0`. Словарный подбор восстанавливает пароль
`monitoring`. После входа под `operator` можно прочитать `/opt/aegishive/processor.py`.
Адреса относятся к текущей SSH-сессии и могут измениться при переподключении.

## Три ошибки в обработчике

1. Из `SO_PEERCRED` берётся только PID. Вместо полученных от ядра uid/gid обработчик
   позже читает `/proc/<pid>/cmdline` и `/proc/<pid>/status`. Между подключением и
   проверкой процесс может вызвать `execve` и изменить эти данные, сохранив PID.
2. В списке разрешённых каталогов пропущена запятая: `"admin" "security"` становится
   строкой `"adminsecurity"`. Пользователь может создать такой каталог.
3. Архив создаётся от root командой `tar -chf`. Флаг `-h` заставляет tar читать цель
   символической ссылки.

Скрипт задерживает однопоточный обработчик в `recv()` одним соединением, а другие
ставит в очередь. После подключения каждый процесс вызывает
`execve("/usr/bin/su", ["managectl", "root"], env)`. Процесс `su` имеет effective UID 0
и ждёт пароль на открытом pipe; имя команды уже соответствует ожидаемому `managectl`.
Когда обработчик перечитывает `/proc`, проверка проходит.

Используются 25 параллельных попыток при лимите `pids.max=50`. Ссылка помещается
в `/data/adminsecurity`, а не в sticky-каталог `/data`: иначе её разыменование
блокирует `fs.protected_symlinks=1`.

## Запуск

После перехода на `hv-storage-01` под `operator` перенесите туда
[exploit.py](exploit.py) и запустите:

```bash
python3 exploit.py
```

Скрипт создаёт каталог и ссылку, выполняет гонку, ждёт архив в `/data/backup/` и читает
из него флаг. Локальный запуск на рабочем компьютере эту среду не воспроизводит.
Исходники обработчика и SMB-скрипт остаются на машине задания; в Git сохранён
[FLAG.txt](FLAG.txt).

Исправление — проверять uid/gid из `SO_PEERCRED` и архивировать ссылки как ссылки,
не разрешая пользовательскому пути выйти за пределы каталога резервного копирования.
