# io_hrana — write-up (task8)

**Avito CTF 2026 · категория «Reversing»**
**Цель:** «аттестоваться» у сторожевого шершня (`io_hrana.elf`) и попасть в улей — бинарь сам отдаёт флаг.
**Дано:** `io_hrana.elf` — `ELF 64-bit LSB executable, x86-64, statically linked, stripped`.

---

## 1. Разведка (три «слепые зоны» и как они возникли)

Здесь необычно всё: этот таск — не «введи пароль», а «создай нужную обстановку». Разведка натыкается на три стены подряд, и каждая — подсказка.

**1) `strings` не находит НИЧЕГО осмысленного.** Обычно в бинаре видны сообщения/подсказки. Здесь — пусто. Причина: `main` — это гигантский (~930 КБ) кусок кода, который **побайтово собирает ~130 КБ зашифрованного блоба** инструкциями `movb $imm, ...` и расшифровывает строки на лету (разделитель `"gbi0"`). То есть готовых строк в файле нет — их не видят ни `strings`, ни `rabin2`.

**2) `strace` тоже почти пуст — где сисколлы?** Под трассировкой не видно ни `open`, ни `read`, ни `connect`. Разгадка — в имени: **io_hrana ≈ io_uring**. Всё I/O идёт через **io_uring в режиме SQPOLL**: заявки кладутся в кольцевой буфер, их разбирает kernel-поток, а результаты читаются из другого кольца — **без классических сисколлов**. Поэтому `strace`/`ltrace` слепы.

**3) Бинарь не запускается вообще.** Под Docker/qemu он падает сразу: `ENOSYS` на сисколле `425 = io_uring_setup`. Причина: arm64-хост (Mac), Docker крутит arm64-ядро, а `qemu-user` не эмулирует io_uring. Вывод: нужен **настоящий x86-64 Linux-кернел с io_uring**. Поднял его через `colima --arch x86_64` (kernel 6.8) — и бинарь ожил.

**4) Он спрашивает не меня, а систему.** Запускаю — он что-то проверяет и выходит. Реверс функции проверок (`0x402e5e`) показывает: бинарь читает `/proc/1/comm`, `/etc/os-release`, проверяет пользователя и время создания его домашней папки. То есть «докажи, что не робот/верблюд/медоед» = **приведи окружение к нужному виду**, а не введи строку. Это и есть «печати аттестации».

**5) Последний секрет он отдаёт по сокету, которого не видно.** Пройдя проверки среды, бинарь пытается куда-то подключиться (io_uring `connect`), но `strace` молчит. Ставлю **kernel kprobe на `unix_stream_connect`** — и вижу: он коннектится к **абстрактному Unix-сокету `@h0n3ycOmb`**. Поднимаю на этом имени слушатель — бинарь подключается и **присылает флаг**, печатает `[+] ALL DONE`.

Мораль разведки: три «слепые зоны» снимаются тремя приёмами — понять обфускацию строк, понять io_uring, поднять правильный кернел; а «пароль» оказался слепком среды.

## 2. Уязвимость / механика (что именно проверяется и почему это «дыра»)

«Гейт» — это набор проверок окружения, каждую из которых можно **воссоздать**, а не сломать. Это и есть аттестация «не робот / не верблюд / не медоед»:

| # | Что проверяет бинарь | Как удовлетворить |
|---|---|---|
| 1 | `/proc/1/comm` НЕ должен быть `systemd` (мы не «обычная» система) | запуск как PID 1: `unshare -m -p -f --mount-proc ./io_hrana.elf` |
| 2 | `/etc/os-release` должен содержать `ID=PROpolisOS` (propolis = пчелиный клей) | bind-mount поддельного `os-release` |
| 3 | реальный юзер **`apis_mellifera`** (медоносная пчела), home `/home/apis_mellifera`, и **btime папки = 13:37 MSK** (10:37 UTC, «leet o'clock») | `useradd` + пересоздать home ровно при системных часах 10:37 UTC |
| 4 | коннект к абстрактному сокету **`@h0n3ycOmb`** («honeycomb») за «паролем» | поднять слушатель на `@h0n3ycOmb` → бинарь присылает флаг |

Почему это работает: бинарь не сверяет ввод с секретом — он делает `statx`/чтение по среде и сравнивает с зашитыми (зашифрованными) значениями. Значит «ключ» — это не строка, а **точная конфигурация процесса и файловой системы**. Проверка 3 самая тонкая: `btime` папки берётся `statx`-ом, поэтому папку надо создать в тот момент, когда системное время равно 10:37 UTC (13:37 MSK — «часы 13:37» + пчелиный мотив).

## 3. Эксплуатация шаг за шагом (воспроизведение)

Нужен x86-64 Linux с io_uring. На Mac — через colima.

### Шаг 1. x86-64 VM с настоящим io_uring-кернелом

```bash
brew install lima-additional-guestagents
colima start --profile x86 --arch x86_64      # kernel 6.8
colima ssh --profile x86                       # дальше всё внутри VM (Ubuntu)
```

### Шаг 2. Пользователь-пчела с нужным btime папки

```bash
sudo useradd -m apis_mellifera 2>/dev/null || true
sudo rm -rf /home/apis_mellifera
sudo date -u -s '10:37:00'                     # 13:37 MSK; отматываем часы на момент создания
sudo mkdir -p /home/apis_mellifera
sudo chown apis_mellifera:apis_mellifera /home/apis_mellifera
sudo hwclock --hctosys 2>/dev/null; sudo ntpdate pool.ntp.org 2>/dev/null || true   # вернуть время
```

(На практике btime-часть тонкая: проще всего создать папку ровно когда системное время = 10:37 UTC, затем вернуть часы.)

### Шаг 3. Поддельный os-release + слушатель на abstract-сокете `@h0n3ycOmb`

```bash
printf 'ID=PROpolisOS\n' | sudo tee /tmp/os-release
python3 - <<'PY' &
import socket
s = socket.socket(socket.AF_UNIX, socket.SOCK_STREAM)
s.bind('\0h0n3ycOmb'); s.listen(1)     # ведущий \0 = abstract namespace
c, _ = s.accept(); print('[flag]', c.recv(4096))
PY
```

### Шаг 4. Запуск как PID 1 + подмена os-release под io_uring-кернелом

```bash
sudo unshare -m -p -f --mount-proc bash -c \
  'mount --bind /tmp/os-release /etc/os-release; exec ./io_hrana.elf'
# -> бинарь проходит 4 проверки, слушатель печатает флаг, сам бинарь -> [+] ALL DONE
```

Как открывался сокет `@h0n3ycOmb`: он не виден в `strace` (io_uring), поэтому имя добыто через **kernel kprobe на `unix_stream_connect`**. После прохождения проверки 3 бинарь дополнительно печатает prize-URL `https://prizering-ij8tatnw.avitoctf.ru/` — это «отсылка для своих» (Unicode-Tag стего в этом бинаре нет).

### Ключевые адреса (реверс)

`main` @ `0x40b305`; проверки среды @ `0x402e5e`; секрет по сокету @ `0x409108`; io_uring-обёртки: setup `0x4f4f7f`, enter `0x4f5609+`, register `0x4f5e24+`; malloc-like `0x51d650`.

### Уборка побочных эффектов

В процессе в VM остались профиль `colima` **x86** и пользователь `apis_mellifera`:

```bash
colima stop x86 && colima delete x86
```

## 5. Выводы / уроки

Три приёма анти-анализа и как каждый бьётся:

- **Строки собираются рантаймом** из `movb`-иммедиатов и расшифровываются (разделитель `gbi0`) → статический `strings`/`rabin2` бесполезен, нужна расшифровка блоба в динамике.
- **io_uring в режиме SQPOLL** уводит все сисколлы из-под `strace`/`ltrace` → видимость возвращает только kernel-tracing (kprobe/eBPF на `unix_stream_connect` и т.п.).
- **«Пароль» — не ввод, а слепок среды** (PID 1 / `os-release` / user / btime папки) → решается воссозданием окружения, а не написанием solver'а.

И главный урок про сам запуск: осознать, что нужен **настоящий x86-64 io_uring-кернел**, а не `qemu-user`, — иначе бинарь падает на `ENOSYS` ещё до всякого реверса.
