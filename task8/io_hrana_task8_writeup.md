# io_hrana — write-up (task8)

**Avito CTF 2026 · категория «Reversing»**
**Цель:** «аттестоваться» у сторожевого шершня (`io_hrana.elf`) и попасть в улей — бинарь сам отдаёт флаг.
**Дано:** `io_hrana.elf` — x86-64, статический, stripped.

## Флаг (уже добыт)

```
avito{tim3_1s_h0ney&hon3y_i5_7ime}
```

Тема: «time is honey & honey is time» — часы `13:37` + пчелиный мотив. Флаг бинарь передал сам по Unix-сокету, когда окружение прошло его «аттестацию». **Задача решена — тебе не нужно ничего доделывать**, ниже объясняю, как я до этого дошёл, и как воспроизвести, если захочешь повторить руками.

## Как я до этого дошёл (по-человечески)

Здесь необычно всё: этот таск — не «введи пароль», а «создай нужную обстановку». Хронология:

1. **`strings` не находит НИЧЕГО осмысленного.** Обычно в бинаре видны подсказки/сообщения. Здесь — пусто. Причина: `main` — это гигантский (~930 КБ) кусок кода, который **побайтово собирает ~130 КБ зашифрованного блоба** инструкциями `movb $imm, ...` и расшифровывает строки на лету (разделитель `"gbi0"`). То есть строки не лежат в файле готовыми — их нет для `strings`/`rabin2`.

2. **`strace` тоже почти пуст — где сисколлы?** Запускаю под трассировкой — не видно ни `open`, ни `read`, ни `connect`. Разгадка в имени: **io_hrana ≈ io_uring**. Всё I/O идёт через **io_uring в режиме SQPOLL**: заявки кладутся в кольцевой буфер, их разбирает kernel-поток, а результаты читаются из другого кольца — **без классических сисколлов**. Поэтому strace/ltrace слепы.

3. **Бинарь не запускается вообще.** Под Docker/qemu он падает сразу: `ENOSYS` на сисколле `425 = io_uring_setup`. Причина: у меня arm64-хост (Mac), а Docker крутит arm64-ядро; qemu-user не эмулирует io_uring. Вывод: нужен **настоящий x86-64 Linux-кернел с io_uring**. Поднял его через `colima --arch x86_64` (kernel 6.8) — и бинарь ожил.

4. **Он спрашивает не меня, а систему.** Запускаю — он что-то проверяет и выходит. Реверсом функции проверок (`0x402e5e`) вижу: он читает `/proc/1/comm`, `/etc/os-release`, проверяет пользователя и время создания его домашней папки. То есть «докажи, что не робот/верблюд/медоед» = **приведи окружение к нужному виду**, а не введи строку. Это и есть 4 «печати аттестации».

5. **Последний секрет он отдаёт по сокету, которого не видно.** После прохождения 3 проверок бинарь пытается куда-то подключиться (io_uring `connect`), но strace молчит. Ставлю **kernel kprobe на `unix_stream_connect`** — и вижу: он коннектится к **абстрактному Unix-сокету `@h0n3ycOmb`**. Поднимаю на этом имени слушатель — бинарь подключается и **присылает флаг**, печатает `[+] ALL DONE`.

Мораль хронологии: три «слепые зоны» (нет строк, нет сисколлов, не запускается) снимаются тремя приёмами — понять обфускацию, понять io_uring, поднять правильный кернел; а «пароль» оказался слепком среды.

## 4 проверки окружения и как каждую удовлетворить

Это и есть гейт «не робот / не верблюд / не медоед»:

| # | Что проверяет | Как обойти |
|---|---|---|
| 1 | `/proc/1/comm` НЕ должен быть `systemd` | запуск как PID 1: `unshare -m -p -f --mount-proc ./io_hrana.elf` |
| 2 | `/etc/os-release` должен иметь `ID=PROpolisOS` (propolis = пчелиный клей) | bind-mount поддельного `os-release` |
| 3 | реальный юзер **`apis_mellifera`** (медоносная пчела), home `/home/apis_mellifera`, и **btime папки = 13:37 MSK** (10:37 UTC, «leet o'clock») | `useradd`, пересоздать home при системных часах 10:37 UTC → печатает prize-URL `https://prizering-ij8tatnw.avitoctf.ru/` |
| 4 | коннект к абстрактному сокету **`@h0n3ycOmb`** («honeycomb») за «паролем» | поднять слушатель на `@h0n3ycOmb` → бинарь присылает флаг |

## Пошаговое воспроизведение (если хочешь повторить)

Нужен x86-64 Linux с io_uring. На Mac — через colima:

```bash
# 1) x86-64 VM с настоящим io_uring-кернелом
brew install lima-additional-guestagents
colima start --profile x86 --arch x86_64      # kernel 6.8
colima ssh --profile x86                       # дальше всё внутри VM (Ubuntu)

# 2) внутри VM: пользователь-пчела с нужным btime папки
sudo useradd -m apis_mellifera 2>/dev/null || true
sudo rm -rf /home/apis_mellifera
sudo date -u -s '10:37:00'                     # 13:37 MSK; ставим часы назад на время создания
sudo mkdir -p /home/apis_mellifera
sudo chown apis_mellifera:apis_mellifera /home/apis_mellifera
sudo hwclock --hctosys 2>/dev/null; sudo ntpdate pool.ntp.org 2>/dev/null || true   # вернуть время

# 3) поддельный os-release + слушатель на abstract-сокете @h0n3ycOmb (в фоне)
printf 'ID=PROpolisOS\n' | sudo tee /tmp/os-release
python3 - <<'PY' &
import socket
s=socket.socket(socket.AF_UNIX, socket.SOCK_STREAM)
s.bind('\0h0n3ycOmb'); s.listen(1)   # ведущий \0 = abstract namespace
c,_=s.accept(); print('[flag]', c.recv(4096))
PY

# 4) запуск как PID 1 + подмена os-release, всё под io_uring-кернелом
sudo unshare -m -p -f --mount-proc bash -c \
  'mount --bind /tmp/os-release /etc/os-release; exec ./io_hrana.elf'
# -> бинарь пройдёт 4 проверки и слушатель напечатает avito{tim3_1s_h0ney&hon3y_i5_7ime}
```
(На практике btime-часть тонкая: `btime` папки берётся `statx`-ом; проще всего создать папку ровно когда системное время = 10:37 UTC, затем вернуть часы.)

## Ключевые адреса

`main` @ `0x40b305`; проверки среды @ `0x402e5e`; секрет по сокету @ `0x409108`; io_uring-обёртки: setup `0x4f4f7f`, enter `0x4f5609+`, register `0x4f5e24+`; malloc-like `0x51d650`.

## Уборка (побочные эффекты)

В процессе решения в VM остались профиль `colima` **x86** и пользователь `apis_mellifera`. Почистить:
```bash
colima stop x86 && colima delete x86
```

## Мораль

Три приёма анти-анализа и как они бьются:
- строки собираются рантаймом из `movb`-иммедиатов → статический `strings` бесполезен, нужна расшифровка блоба;
- io_uring SQPOLL уводит все сисколлы из-под strace/ltrace → нужен kernel-tracing (kprobe/eBPF);
- «пароль» — не ввод, а слепок среды (PID1 / os-release / user / btime) → решается воссозданием окружения, а не solver'ом.
Ключ к самому запуску — осознать, что нужен настоящий x86-64 io_uring-кернел, а не qemu-user. Unicode-Tag стего в этом бинаре нет; аналог «отсылки для своих» — prize-URL `https://prizering-ij8tatnw.avitoctf.ru/`.
