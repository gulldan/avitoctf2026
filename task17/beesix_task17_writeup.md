## Протокол (из server.py / client.py)

1. `Enter secret:` → шлём secret (у нас есть) → `Access granted!`.
2. ECDH на SECP256R1: клиент шлёт свой pubkey (DER SPKI) фреймом (`!I` len + payload), сервер отвечает своим. `key = SHA256(ECDH_shared)`.
3. Защищённый канал: `payload = IV(16) + AES-CBC(key, PKCS7(pt))`, `tag = SHA256(key ‖ payload)`, фрейм = `payload+tag`.
4. Приложение: `login:`/`password:` (в исходнике `test`/`test`, но на бою — другие!), затем команды `list`/`read <file>`/`help`/`quit`.

## Три бага, которые складываются в цепочку

**1. Статичный приватный ключ сервера.** `SERVER_PRIVATE_KEY` грузится один раз при импорте (`server.py:69`) → **у всех соединений один и тот же ECDH-ключ сервера**. Проверено: серверный pubkey в `traffic.pcap` (`a589ff20…2ec661`) байт-в-байт совпадает с живым сервером. Следствие: **если переиграть (replay) захваченный pubkey агента 0x00B на живой сервер, он выведет ту же сессионную `key`, что и в перехвате** — при этом саму `key` мы не узнаём.

**2. Самопальный MAC `SHA256(key ‖ payload)`** вместо HMAC (`server.py:168`). Конструкция Меркла–Дамгарда → **уязвима к length-extension**: имея любую пару `(payload, tag)` из pcap, можно вычислить валидный tag для `payload ‖ glue ‖ X` при любом нашем `X`, **не зная `key`**.

**3. MAC-then-decrypt с различимой ошибкой паддинга** (`server.py:176–190`). Сервер сначала проверяет MAC, потом снимает PKCS7 (бросает `DecryptionError` на плохом паддинге). Так как баг #2 позволяет ковать валидные MAC, получаем рабочий **CBC padding oracle**. Оракул-сайдченел — **длина ответного фрейма** (ответы тоже шифрованы): в состоянии «ждём login» валидный паддинг → сервер принимает мусорный login и отвечает `password:` = **64 байта**; невалидный → `ERROR: decryption failed` = **80 байт**.

## Эксплойт (скрипты в `task17/`)

- `parse_pcap.py` / `carve.py` — пересобрать TCP-потоки и вырезать фреймы. В переписке: клиент прислал login, password, одну команду (по 1 блоку); сервер — `login:`, `password:`, 55-символьный баннер `Authenticated…` (4 блока — доказывает, что 0x00B вошёл НЕ по test/test), затем 1-блочный ответ.
- `sha256ext.py` — чистый Python SHA256 length-extension. База = `key(32) ‖ P0(32)` (P0 — payload захваченного фрейма), `glue = md_pad(64)` = 64 байта; кованый фрейм = `P0 ‖ glue ‖ (C' ‖ C_target)` + продолженный tag.
- `solve_oracle.py` (он же `oracle.py`) — для каждого целевого блока шлёт кованые фреймы с последними двумя блоками `[C', C_target]`, читает длину ответа (64 = валидный паддинг, 80 = невалидный) и крутит стандартный PKCS7-padding-oracle → восстанавливает `D_k(C_target)`, затем `pt = D_k(C_target) ⊕ IV`. ~40 мс/запрос, ~8500 запросов, с переподключением после каждого валидного хита.
