# Не пойман — не медоед (HoneyLeak)

**Флаг:** `avito{c0ngr4t5_0n_cr4ck1ng_th3_sh3ll}`

В nginx access log среди 56 873 записей четыре запроса используют редкий User-Agent
`Trident/6.0`. Все обращаются к одному ASPX webshell и содержат команды PowerShell
в Base64. По ним восстанавливаются путь SQL-дампа, пароль архива и адрес выгрузки.

## Поиск архива

Команды показывают разведку на сервере, создание ZIP с паролем и отправку на C2.
Имя файла вычислялось из времени отдельно при упаковке и при отправке, поэтому эти
имена не совпадают. Искать архив только по расширению или времени из команды нельзя.

На учебном C2 была открыта выдача каталога. Первые четыре байта файлов проверялись
HTTP Range-запросами: ZIP начинается с `50 4b 03 04`, то есть `PK\x03\x04`.
Так найден `blob_3po654ppbr.log`, несмотря на расширение `.log`.

Пароль из команд webshell — `S7m!vQ2@rK9Lp4X_2026`. Внутри архива лежит
`corp_finance_2026_07_03.sql`; флаг записан в `secrets.incident_flag`.

## Запуск

Локальная проверка требует исходного журнала и скачанного ZIP. В Git их нет:

```bash
uv run python honeyleak/recover_secret.py \
  --log honeyleak_access.log --blob honeyleak/real_blob.bin
```

[recover_secret.py](recover_secret.py) декодирует команды, извлекает пароль и читает
флаг из архива. Опция `--probe-c2` повторяет поиск по сигнатуре ZIP, если учебный C2
ещё доступен; при неудаче используется файл из `--blob`.

Сохранённый результат — [FLAG.txt](FLAG.txt). Расширение файла и заявленный
Content-Type здесь ненадёжны: формат определяется по содержимому.
