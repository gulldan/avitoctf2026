# Government

**Флаг:** `avito{hoN3Y_BAdgERS_allOwEd_1N_beehIVe_N0w}`

Портал Government принимает и обычные `sess_…`, и интеграционные `hof365_…` токены.
Последние дают доступ к удалению документов без проверки роли. Такой токен удаётся
получить у Intercom Fin, представившись чужим пользователем.

## Решение

В Intercom отключена Messenger Identity Verification. При запуске виджета клиент
может указать `email=queen@hive.gov`, и сервер не требует подтверждения этой личности.
Агент поддержки доверяет адресу и по запросу выдаёт HoneyOffice 365 API key.

Из ответа извлекается строка вида `hof365_[A-Za-z0-9]+`. Портал принимает её как
Bearer-токен для административного запроса:

```bash
curl -s -X DELETE https://government-dtpd4cpr.avitoctf.ru/api/documents/1 \
  -H 'Authorization: Bearer <полученный hof365_токен>'
```

Ответ имеет `status: deleted` и сообщение с флагом. Ошибки независимы: поддержка
раскрывает ключ по неподтверждённой личности, а портал не проверяет право владельца
ключа на удаление документа.

## Запуск

Нужны работающие портал, Intercom и установленный Chrome:

```bash
uv run python government/drv.py self-test
uv run python government/drv.py solve
```

`self-test` проверяет извлечение токена из текста. `solve` запускает локальную страницу
и отдельный Chrome, открывает виджет, отправляет запрос, извлекает токен и выполняет
`DELETE`. Адреса экземпляра задаются параметрами скрипта и его окружения; см. `--help`.

## Файлы

[drv.py](drv.py) управляет браузером и запросами к порталу,
[cdp.py](cdp.py) реализует транспорт Chrome DevTools Protocol,
[intercom_boot.html](intercom_boot.html) запускает виджет.

Исправление — подтверждать личность пользователя в Intercom и отдельно проверять
роль и права на документ для каждого запроса к порталу.
