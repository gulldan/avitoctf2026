# СОТЭК

**Флаг:** `avito{vERy_Sus_b4DGeR_Detect3d_bY_cAMerA}`

СОТЭК сохраняет `postalCode`, а позднее вставляет его в SQL внутри
`calculateRatesForUser`. Эта отложенная SQL-инъекция позволяет извлечь активную
сессию владельца заказа и открыть страницу с флагом.

## Проверка условия через тарифы

Несколько SQL-выражений за один запрос драйвер не принимает. Вместо этого используется
`UNION SELECT CASE`, который возвращает известный тариф только при истинном условии:

```sql
x') UNION SELECT CASE WHEN 1=1 THEN 101 ELSE NULL END --
```

После регистрации с таким `postalCode` запрос `POST /api/calculate` включает
`rate_id=101`. Контрольный аккаунт с `1=2` возвращает пустой список. Это даёт один бит
ответа на произвольное SQL-условие.

## Извлечение сессии

Через тот же способ находится пользователь `agent.bzz@hive.local` и его последняя
сессия:

```sql
SELECT token FROM sessions
WHERE user_id = (SELECT id FROM users WHERE email = 'agent.bzz@hive.local')
ORDER BY id DESC LIMIT 1
```

Сначала проверяется длина токена, затем каждый из 36 символов восстанавливается
двоичным поиском по значению `unicode(substr(token, pos, 1))`. Каждый вопрос требует
нового аккаунта с соответствующим `postalCode`.

Токен передаётся как cookie `session_id` при запросе `/orders`. Сервер находит заказ
пользователя и добавляет `process.env.FLAG` в `overlay_text`.

## Запуск

```bash
uv run python sotek/solve_sotek.py --base-url https://sotek-<id>.avitoctf.ru
```

[solve_sotek.py](solve_sotek.py) выполняет контрольные запросы, извлекает актуальную
сессию и получает страницу. Нужен работающий экземпляр с активной сессией целевого
пользователя. Исходный архив `sotek_4d9e047.zip` не включён в Git.

Параметризованный запрос в `calculateRatesForUser` устраняет причину ошибки.
Проверять тип и формат нужно и при регистрации, но хранение строки в базе не делает
её безопасной для последующей конкатенации в SQL.
