# Ghost Font — write-up (task2)

**Avito CTF 2026 · категория «Стеганография»**

## 1. Условие задачи

Разведчик прислал не видео, а один «шумный» скриншот сервиса **Ghost Font**. На картинке
скрыто послание — и это флаг. Нужно прочитать текст, который человек ловит глазом, но OCR/нейросеть
видят как случайный крап.

**Дано:** `ghost_screenshot.png` (~988 КБ) — один кадр анимации Ghost Font (браузерный скриншот
с хромом окна вокруг холста).

Весь разбор автоматизирован в `task2/decode_ghost.py`; промежуточные картинки-эксперименты
(`ghost_down*.png`, `ghost_density*.png`, `ghost_fft.png`, `ghost_coarse.png`, `ghost_decoded.png` и т.д.)
лежат рядом.

## 2. Разведка

**Что видно глазом.** Весь холст — чёрно-белые точки на регулярной сетке. Никакой видимой
структуры: для человека на одном статичном кадре это тоже почти шум, а буквы «оживают» только
в движении (см. ниже). Значит секрет — визуальный, но спрятан не в цвете.

**Проверка «а вдруг байтики в файле».** Первым делом `inspect_png` (в `decode_ghost.py`) разбирает PNG
по чанкам, сверяет CRC каждого чанка и считает «хвост» после `IEND`:

```
Parsed end: <N>; file size: <N>; trailing bytes: 0
```

Все CRC валидны, лишних байт после `IEND` нет → в метаданных/после конца файла ничего не спрятано.
Это сразу **отметает** версию «данные внутри байтов PNG» и переводит фокус на **пиксели**.

**Что НЕ сработало (и почему это важный вывод).**

- Каналы R/G/B, LSB-битовые плоскости — поле монохромное, секрета в цвете и младших битах нет.
- `strings` / `exiftool` / `binwalk` — файл чистый, байтового секрета нет.
- Downscale и карты плотности точек (`ghost_down*.png`, `ghost_density*.png`) — текст **слабо
  проступает**, но грязно. Уже здесь появилась гипотеза: раз при огрублении масштаба возникает
  разница текстуры, значит буквы отличаются от фона какой-то **регулярной** характеристикой сетки,
  а не яркостью отдельных точек.

**Ключевая зацепка — в легенде.** Прислали **скриншот вместо видео**. Ghost Font — это *анимация*
бегущего поля случайных точек. В движении глаз ловит когерентную (одинаково движущуюся)
область и «видит» буквы, а любой отдельный кадр для OCR — просто случайный крап. У нас всего один
кадр, поэтому тот же приём делаем **пространственно**: ищем регулярную аномалию сетки и/или
коррелируем кадр с его собственной сдвинутой копией.

## 3. Уязвимость (как устроено кодирование)

Ghost Font прячет текст **двумя** привязанными к области букв способами одновременно:

1. **Фаза 6-пиксельной решётки точек — основной читаемый сигнал.** Всё поле — точки на сетке
   `6×6` px (`CELL_SIZE = 6`). Ячейки фона и ячейки букв отличаются **не** плотностью и **не** цветом,
   а **фазовым сдвигом** ячейки по вертикали. Именно поэтому downscale «намекал» на текст: усреднение
   по грубому масштабу чуть-чуть по-разному гасит точки с разной фазой.

2. **Самоналожение (overlay) сдвинутой копии атласа.** Область букв дублирует один и тот же
   случайный «атлас» точек второй копией: по X фиксированный сдвиг `294 px` (`SIGNAL_X_OFFSET`),
   по Y — направление противоположное, величина подбирается корреляцией. Совпадение двух копий
   даёт **резкую, но шумную** карту букв.

Почему это «уязвимо» для расшифровки: фазовый сдвиг решётки — детерминированная периодическая
метка, её ловит согласованный фильтр (несущая `exp(-2πi·y/6)`), а overlay-копия — это автокорреляция
внутри одного кадра, которую видно через FFT. Ни то, ни другое не требует второго кадра.

## 4. Эксплуатация шаг за шагом (по `decode_ghost.py`)

**Шаг 1. `inspect_png` — исключить байтовый стего.** Разбор чанков + CRC + «хвост». Вывод:
секрет чисто визуальный (см. Разведку).

**Шаг 2. `normalize_canvas` — убрать хром браузера и вернуть исходное разрешение.**
На скриншоте вокруг холста рамка окна. Функция:
- находит верх холста как первую строку с сотнями тёмных пикселей (`gray < 100`), тогда как строки
  тулбара имеют лишь единицы;
- берёт самый длинный «прогон» столбцов, плотно занятых точками, — это горизонтальные границы
  холста `1280×720` (`CANVAS_WIDTH/HEIGHT`);
- по ширине вычисляет масштаб скриншота и **пересемплирует обратно** в исходные пиксели холста,
  привязываясь к сетке `CELL_SIZE`.

```
Canvas bounds: x=[left, right), y=top; scale=...; recovered size=1280xH
```

Зачем: дальнейшие детекторы завязаны на период 6 px, поэтому кадр надо вернуть в «пиксель-в-пиксель»
исходного холста, иначе фаза/сдвиги «поплывут».

**Шаг 3. `carrier_score` — фазовый детектор (ядро, читается сам по себе).**
Бинаризуем точки (`пиксель < 100` → «чёрная»), домножаем на комплексную несущую `exp(-2πi·y/6)`
периода 6 px, вычитаем фоновую фазу (посчитанную по рамке кадра шириной 40 px) и берём локальное
усреднение (box-mean, радиусы 24 и 9):

```python
phase   = np.exp(-2j * np.pi * np.arange(height)[:, None] / CELL_SIZE)
carrier = dots * phase
background_phase = carrier[border].mean()
local_phase = box_mean(carrier, radius=24)
return box_mean(np.abs(local_phase - background_phase), radius=9)
```

Там, где фаза ячейки отличается от фоновой, — буквы. **Этой карты (`ghost_coarse.png`) уже достаточно,
чтобы прочитать `SM4RT3R / TH4N AI`.**

**Шаг 4. `find_vertical_shift` — найти вторую копию атласа через FFT-корреляцию.**
По X сдвиг известен (`SIGNAL_X_OFFSET = 294`, ширина атласа `ATLAS_WIDTH = 1296`), по Y величина
неизвестна — её берём как `argmax` круговой корреляции столбцов через FFT:

```python
correlation = np.fft.ifft(np.conj(left_fft) * right_fft, axis=0).real.sum(axis=1)
shift = int(np.argmax(correlation))    # -> "Matched atlas vertical shift: <shift>/720 pixels"
```

**Шаг 5. `recover_visual` — резкость от наложения × маска фазы.**
Накладываем поле точек на его же копию, сдвинутую на `(Δx = 294, Δy = найденный)`, считаем локальное
пиксель-в-пиксель **совпадение** (`equality`, резко, но шумно), нормируем весами. Затем перемножаем
резкую overlay-карту с грубой фазовой из шага 3:

```python
rendered = np.clip((exact - 0.40) / 0.60, 0, 1)
rendered *= np.clip((coarse - 0.025) / 0.035, 0, 1)   # оставить резкость только там, где фаза говорит «буквы»
```

Идея: **фаза устойчива, но размыта; наложение атласа резко, но шумно — их произведение оставляет
чёткие буквы только там, где оба метода согласны.**

**Шаг 6. `save_cropped_visual` — обрезать по области текста** (`region = coarse > 0.06`) и сохранить
`ghost_decoded.png`.

**Воспроизведение:**

```bash
cd task2
python3 decode_ghost.py ghost_screenshot.png -o ghost_decoded.png
# на выходе маска с текстом: SM4RT3R / TH4N AI
```

Зависимости: `numpy`, `Pillow` (`pip install numpy pillow`).

**Чтение результата.** На восстановленной маске читается `SM4RT3R` (верхняя строка) и `TH4N AI`
(нижняя) → «smarter than AI» лит-спиком (A→4, E→3; финальные «AI» — обычные A и I). Служебный
водяной знак «WRITTEN IN GHOST FONT» на этом кадре не проявился ни одним методом — он в другом
кадре/слое анимации и к флагу не относится.

## 6. Выводы / уроки

- **Сначала отсекай дешёвые гипотезы.** Разбор PNG-чанков за секунду доказал, что секрет визуальный,
  и сэкономил время на `strings`/LSB/каналах.
- **«Скриншот вместо видео» — это подсказка к методу, а не к содержанию.** Анимация прячет текст
  во временну́ю когерентность; на одном кадре тот же приём переносится в пространство —
  через периодичность сетки и автокорреляцию.
- **Согласованный фильтр бьёт «на глаз».** Фазовый детектор на несущей `exp(-2πi·y/6)` вытаскивает
  регулярную метку решётки чисто, тогда как downscale/карты плотности дают лишь грязный намёк.
- **Комбинирование сигналов = чистый результат.** Устойчивый-но-размытый (фаза) × резкий-но-шумный
  (overlay) даёт читаемые буквы там, где методы согласуются.
