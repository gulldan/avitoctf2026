# PAMgate

**Флаг:** `avito{3a5Y_4DMIN_1NCREmeNt}`

Модуль `pam_pamgate.so` копирует FTP-пароль через `strcpy` в 10-байтный буфер.
Переполнение меняет TOTP-секрет и индекс записи в журнал. После проверки TOTP
выполняется `g[(int16_t)idx]++` без проверки границ: можно увеличить один байт в куче.

## Из admim в admin

Регистрация `admin` запрещена, но `admim` допустима. Последняя буква отличается
ровно на единицу: `0x6d + 1 = 0x6e`. Если инкремент попадёт в пятый байт `PAM_USER`,
имя станет `admin`.

`vsftpd` перечитывает `PAM_USER` после `pam_authenticate()` и подставляет его в
`local_root=/srv/ftp/$USER`. Поэтому уже открытая FTP-сессия попадает в `/srv/ftp/admin`.
Выполнять код или перезаписывать адрес возврата для этого не требуется.

## Формат пароля

Пароль длиной 62 байта устроен так:

| Байты | Значение |
|---|---|
| `0:6` | TOTP для выбранного секрета |
| `6` | `X` |
| `7:9` | знаковый индекс `int16`, little-endian |
| `46:62` | `AAAAAAAAAAAAAAAA` — новый Base32-секрет |

Индексы, содержащие NUL, CR или LF, пропускаются: эти байты изменят обработку строки
или FTP-команды. Перебирается диапазон `[-0x2000, -0x6C0)` с условием `idx & 0xf == 4`,
соответствующим положению буквы внутри выровненного выделения памяти.

После каждого входа читается `stats.txt`. Если там `user: admin`, `flag.txt` нужно
получить сразу в том же соединении: новый дочерний процесс может иметь другую кучу.

## Запуск

Перенесите [solve_pamgate.py](solve_pamgate.py) на машину задания и запустите под
`player`. Адрес `127.0.0.1:30029` относится к FTP внутри этой машины:

```bash
python3 /tmp/solve_pamgate.py
```

Проверка одного ранее найденного индекса:

```bash
python3 /tmp/solve_pamgate.py --index -6940
```

Значение `-6940` сработало в исследованной сессии, но не гарантировано после нового
подключения. Параметры доступа — в [task.md](task.md); бинарник PAM в Git не включён.

Исправление требует ограничить копирование пароля, проверить индекс журнала и
использовать одно и то же проверенное имя на этапах аутентификации и выбора каталога.
