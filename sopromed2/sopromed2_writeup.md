# Сопромёд, часть 2

**Флаг:** `avito{0Tp_ch3ck3D_beF0R3_C4PtcH4_O0PS}`

Для выдачи экзаменационных ответов сервер принимает трёхзначный OTP и reCAPTCHA.
Даже без действующей CAPTCHA ответы различают неверный OTP и кандидата, который
прошёл эту проверку. Так можно перебрать `000…999`, решив CAPTCHA только для последнего запроса.

## Различие ответов

Сначала используются реквизиты из [первой части](../sopromed/sopromed_writeup.md).
Запрос с неподходящим OTP возвращает `invalid_otp`, а подходящий кандидат меняет
ответ. Это раскрывает результат проверки OTP до окончательной проверки CAPTCHA.

В исследованном экземпляре подошёл код `349`. Значение относится к конкретному
стенду; скрипт перебирает его заново.

## Запуск

```bash
CAPTCHA='<valid-recaptcha-token>' uv run python sopromed2/solve_sopromed2.py
```

[solve_sopromed2.py](solve_sopromed2.py) входит в сервис, проверяет различия ответов,
перебирает OTP и запрашивает ответы. Токен также можно сохранить в
`sopromed2/captcha.txt`; этот файл не включается в Git.

`invalid_otp` не означает, что CAPTCHA принята. Окончательный успех подтверждают
только HTTP 200 и данные с флагом. Если финальный запрос отклонён, для найденного
OTP нужен свежий токен.

Исправление — не раскрывать результат проверки OTP до проверки CAPTCHA, ограничивать
попытки и привязывать одноразовые значения к текущей сессии и действию.
