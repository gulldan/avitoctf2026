# Медофильтр 2

**Флаг:** `avito{NEv3R_goNn4_G3T_In_qU3Ue_fOR_HonEY_7wiCE!}`

Во второй версии используется тот же уязвимый HTTP-парсер, что и в
[Медофильтре](../filter/filter_writeup.md). Для обеих задач достаточно одного скрипта.

## Условия срабатывания

`POST /ping` отражает управляемое тело ответа. Сброс буфера `responce.Add` после
3072 байт смещает начало разбора на подставной HTTP-ответ. Строка `Z` после
`Content-Length: 0` попадает в обработчик trailer, который ожидает двоеточие и
обращается к отсутствующему элементу массива. Go-процесс завершается с panic.

Пока обработчик NFQUEUE отсутствует, `--queue-bypass` разрешает исходящий трафик.
Параллельный запрос `/static/honey.txt` получает флаг. Если быстрые сбои исчерпают
бюджет запуска Supervisor, фильтр может остаться в `FATAL`, но это не обязательное
условие атаки.

Результат зависит от сегментации TCP: для описанного сброса буфера поток `/ping`
должен собраться до порога 3072 байта. В исследованной схеме это выполнялось при
MSS ≤ 1940 на участке CDN → edge. Скрипт перебирает отступ `0..40` и ограничивает
число запросов, поскольку чрезмерная нагрузка может остановить весь контейнер.

## Запуск

Создайте экземпляр через launcher, пройдя CAPTCHA вручную, затем передайте его адрес:

```bash
uv run python filter/solve_filter.py https://filter2-srv-ow2wt9j6.avitoctf.ru
```

[Общий скрипт](../filter/solve_filter.py) одновременно вызывает сбои через `/ping`
и запрашивает `honey.txt`. Успех — ответ с `avito{...}`; сохранённый результат находится
в [FLAG.txt](FLAG.txt).

Для проверки самого парсера нужен исходный архив и Linux-контейнер с NFQUEUE.
Они не входят в окружение `uv`. Механизм ошибки и исправление описаны в первой части.
